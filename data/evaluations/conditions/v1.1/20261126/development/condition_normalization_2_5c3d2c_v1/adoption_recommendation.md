# 후속 적용 후보 판단

운영 추출기에 자동 반영하지 않았다. safe-condition-normalization-subset-v1만 별도 실험으로 고정했다. 전체 draft-v1의 의미 계약이나 신규 속성은 승인/승격하지 않았다.

| 실험·규칙 | 권고 | 근거·조건 |
|---|---|---|
| N1 UNIT_EXACT_V1 | 후속 적용 1순위 후보 | 원문에서 확인된 같은 차원의 단위만 변환. TP1 보존, 신규 TP2, FP2/FN2 해소. schema/근거/참조 오류0. 실제 변환은 년/YEAR 및 %/PERCENT 두 건 |
| N2 MONEY_SCALE_V1 | 표현 일관성 후보로 조건부 검토 | 정확한 금액 배율과 통화가 원문에 있는 경우만. 실제 3억원→300000000 KRW의 의미 보존 확인, 성능 효과0. 속성 차이를 함께 강제 변경하지 않음 |
| N2 NUMERIC_SCALAR_V1 | 합성 검증만; 실제 적용 효과 미측정 | 알려진 수치 속성·연산자·원문 숫자가 같은 문자열만 숫자로 변환. 이번 실제 응답에서는 해당 변환0 |
| N3 RANGE_EXPLICIT_FLAGS_V1 | 이번 성능 개선 규칙으로 채택하지 않음 | 실제 안전 변환0. inclusive 불명확 표현은 보류 유지. 양 flags와 원문 경계가 모두 명확한 별도 자료에서만 후속 검토 |
| N4 alias | 신규 구현 채택 불필요 | 기존 v2와 중복. N0 후보 레코드와 동일. 의미 차이·문맥 의존 alias는 제외 |
| N5 통합 | 조합 호환성 확인; 우선 N1만 별도 적용 검토 | N1과 같은 TP 개선. N2는 일관성만 개선. 순서·중복 적용·멱등성 검증 통과 |

## 채택 기준 확인

모든 arm은 기존 TP 보존, 신규 스키마 오류0, 근거 및 참조 오류0, 자동 판정 허용 증가0, 동일 입력 재현성 조건을 충족했다. N1·N5는 실제 strict F1 개선, N2는 확인 가능한 금액 표현 일관성을 제공한다. 그러나 개발용 표본의 점수만으로 일반 적용을 승인하지 않는다. 변경된 후보 ID와 연결 레코드·보류 로그를 계속 보존해야 한다.

## 채택하지 않은 변환

- APPLICANT_TYPE/BUSINESS_TYPE, 개인주소/사업장, 대표자/팀원, EMPLOYMENT/EMPLOYEE_COUNT, REVENUE 계열 field 간 치환.
- 지역 별칭·도내 지명 추론, 문자열 분할·조건 재분해·표준 범주 코드 추측.
- 원문에 없는 단위 생성, years 같은 계약 미포함 alias의 추가, 통화 추측·환율 변환.
- 최소/최대 경계의 inclusive 기본값, UNKNOWN→null, EXISTS+BOOLEAN 위반 자동 수정.
- 원문과 다른 숫자/단위 조합의 배율 환산 및 이미 정규화된 값의 중복 환산.
- 골든 값·span에 맞추는 수정 및 공고 ID별 예외.

## 후속 작업

우선 단위 규칙과 추적 로그를 별도 feature flag 아래 검토하고, 기존 전체 시스템 테스트·새 출처 합성 사례·경계 사례를 확장한다. 속성 의미 계약·논리 adapter·구조화 출력 개선은 별도 실험으로 유지한다. 이번에는 API 호출, 카탈로그 확장, strict 기준·골든셋 변경, DB 변경, 커밋·푸시를 수행하지 않았다.
