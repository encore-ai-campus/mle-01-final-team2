# 지역 별칭 사전 (v0.2)

> 작성 2026-11-25. 생성 순서는 아래 두 줄이다.
>
> ```
> python tools/build_region_codes.py   # 법정동코드로 코드표 보완 (여러 번 돌려도 같은 결과)
> python tools/build_region_alias.py   # 세 소스의 지역 표기로 별칭 사전 생성
> ```
>
> - 기준 코드표는 `지역_코드표.csv`다. 팀 코드표 234행을 그대로 두고, 행정안전부 **법정동코드 전체자료**(code.go.kr, 2026-11-25 내려받음, `원본/법정동코드_전체자료.txt`)로 보완했다.
> - 입력 기본값은 나라장터 `data/g2b/processed/regions.csv`, K-Startup `data/kstartup/processed/kstartup_cleaned.jsonl`, 기업마당 `data/bizinfo/parsed/<최신>/notices.jsonl`이다. 다른 파일을 쓰려면 `--g2b`, `--kstartup`, `--bizinfo`로 지정한다.

공고마다 지역을 다르게 쓴다. 예를 들어 `서울`, `전라남도`, `경기도 안산시 상록구`, `#진주시`, `[부산ㆍ울산ㆍ경남]`처럼 쓴다. 이 사전은 그런 표기를 코드표의 `region_id`에 연결한다.

## 코드표 보완 내용

- **누락 시군구 12개를 넣었다.** 팀 코드표에는 코드 5번째 자리가 0이 아닌 시군구가 빠져 있었다. 빠진 곳은 아래와 같다.
  - 서울: 강북구·광진구·금천구
  - 인천: 연수구·계양구·부평구·미추홀구·제물포구·영종구·서해구
  - 충남 태안군, 충북 증평군
- **일반구 39개를 넣었다** (수원시 장안구 등). `경기도 수원시 장안구`처럼 시와 구를 함께 쓴 표기는 이제 구까지 정확히 연결된다(`exact`).
- **폐지 지역은 `successor_ids`에 지금 코드를 적었다.** 대상은 개편 전 광주광역시·전라남도와 그 시군구, 인천 중구·동구·서구·남구다. 법정동 원본에는 이 대응이 없다. 그래서 인천 대응은 행정 자료로 정한 후보이며 **아직 검수하지 않았다**.
  - 중구 → 제물포구, 영종구
  - 동구 → 제물포구
  - 서구 → 서해구, 검단구
  - 남구 → 미추홀구
- **세종 코드가 원본과 다르다.** 원본의 세종특별자치시 코드는 `3611000000`이다. 팀 코드표는 `3600000000`을 쓴다. 이미 적재한 ID와 어긋나지 않도록 팀 ID를 그대로 두고, `note`에 원본 코드를 적었다.

## 소스별로 지역을 모은 곳

| 소스 | 필드 | 메모 |
|---|---|---|
| 나라장터 | `regions.csv`의 `region_name` | 참가 가능 지역 |
| K-Startup | `support_region_raw` | 시도 약칭만 쓴다 (`전국`, `서울`, `전남광주` 등) |
| 기업마당 | `region_tags` | 시도 약칭 |
| 기업마당 | `hashtags_raw` | 지역으로 읽히는 태그만 센다. 코드표 이름(`진주시`)과 아래 변형 표기를 읽는다. |
| 기업마당 | `jurisdiction_org_name` | 소관기관이 지자체일 때만 센다 |
| 기업마당 | 제목 머리말 `[…]` | `ㆍ`으로 나눠 각각 센다 |

해시태그의 변형 표기는 `alias_type=variant`로 넣고 `note`에 어떻게 읽었는지 적는다. 데이터에서 40개가 나왔고, 같은 공고의 시도 태그·제목과 모두 맞는 것을 확인했다.

- 접미사 생략: `안동` → 안동시, `양구` → 양구군. 이름에 시/군을 붙였을 때 전국에 한 곳뿐일 때만 읽는다.
- 붙여 쓴 시도: `인천남동구` → 인천 남동구
- 특례시: `용인특례시` → 용인시
- 오타·통칭: `충추시` → 충주시, `세종시` → 세종특별자치시. 스크립트의 `TYPOS`에 직접 적는다.

기업마당은 같은 공고 안에서 같은 표기가 여러 번 나와도 1번만 센다. 해시태그 지역은 공고의 지원 대상 지역이라는 뜻이 아니다. 전 시도 태그가 달린 공고가 347건이다(기업마당 명세서 §7). 이 사전은 **표기를 코드에 연결하는 일**만 한다. 지원 대상이 어디인지는 공고 본문에서 정한다.

## 컬럼

| 컬럼 | 값 |
|---|---|
| `alias_type` | • `official`: 공식 시도명<br>• `short`: 약칭 (서울, 충북)<br>• `legacy`: 개편 전 시도<br>• `path`: 시도+시군구(+구) 경로<br>• `legacy_path`: 개편 전 시도 경로<br>• `bare`: 시도 없이 쓴 시군구 이름<br>• `group`: 권역<br>• `variant`: 변형 표기 (해시태그) |
| `granularity` | • `exact`: 같은 단위<br>• `finer`: 표기가 더 세밀함 (읍면동)<br>• `coarser`: 상위로만 연결됨 |
| `status` | • `OK`<br>• `BUNDLE`: 묶음으로 연결됨<br>• `AMBIGUOUS`: 같은 이름이 여러 곳에 있음<br>• `NEEDS_REVIEW`: 인천 개편 전 구 등<br>• `MISSING_CODE`: 코드표에 없음 |
| `target_id`, `target_name` | 연결 대상의 ID와 이름이다. 이름은 코드표의 `full_name`(예: `부산광역시 서구`)이고, 묶음이면 묶음 이름이다. 연결할 때는 항상 `target_id`를 쓴다. |
| `g2b_rows`, `kstartup_rows`, `bizinfo_rows` | 소스별로 그 표기가 나온 행 수다. 기업마당은 공고 수로 센다. |

## 판정에 쓸 때

- **`finer`**: 공고가 읍면동까지 제한한다. 사용자 주소가 시군구 단위면 **UNKNOWN**이다.
- **`coarser`, `NEEDS_REVIEW`**: 시도까지만 확인된다. 시도가 맞아도 **NEEDS_CHECK**이고, 시도가 다르면 UNSATISFIED다.
- **`BUNDLE`**: 묶음을 구성하는 시군구나 시도 중 하나에 속하면 충족이다.
- **`AMBIGUOUS`**: 사전만으로는 정할 수 없다. `서구`, `중구`, `남구`, `동구`, `북구`, `고성군`이 여기에 해당하고 모두 기업마당 해시태그다. 공고별 확인은 `지역_수동확인.csv`에서 한다. 정하지 못하면 NEEDS_CHECK로 둔다.
