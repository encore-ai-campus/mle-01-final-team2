## 2. 출처와 이용 조건

| 항목 | 내용 |
|---|---|
| API | 법령 검색 `lawSearch.do` (target=law/admrul), 본문 조회 `lawService.do` (MST=법령일련번호) |
| 인증 | 법제처 OPEN API 인증값(OC). 환경변수 `LAW_OC`로만 넘기며 **파일·로그에 저장하지 않음** (수집 결과 전체에서 0건 확인) |
| 저작권 | 법령은 저작권법 제7조에 따라 보호 대상이 아님 |
| 이용약관 | 법제처 OPEN API 이용약관은 **미확인**. 외부 공개 전 확인 필요 |

### 2.1 v0.2 추가분 수집 방법 (공개 본문 페이지)

| 단계 | 요청 | 얻는 값 |
|---|---|---|
| 1 | `GET https://www.law.go.kr/법령/<법령명(공백 제거)>` | 숨은 입력값 `lsiSeq`(법령일련번호 = `doc_id`), `efYd`(시행일) |
| 2 | `GET https://www.law.go.kr/LSW/lsInfoR.do?lsiSeq=…&efYd=…&chrClsCd=010202&urlMode=lsInfoP&ancYnChk=0` | 본문 HTML (UTF-8) |
| 3 | 본문에서 장·절 제목(`p.gtit`)과 조문 앵커(`a[name=J{조}:{가지}]`)를 순서대로 읽음. 조문 내용은 `div.lawcon` | `chapter`, `article_no`, `article_title`, `text`, `deleted` |
| 4 | 긴 숫자 J 앵커(부칙)가 나오면 멈춤 | 부칙은 받지 않음 |

- 요청 사이 1초 대기, 인증값 없음.
- 소관부처는 부처명만 남기고 **부서명·전화번호는 저장하지 않는다**(저장 파일에서 전화번호 패턴 0건 확인).
- 본문 형식이 v0.1과 조금 다르다. v0.1은 `제2조(정의)` 뒤에서 줄을 바꾸지만, v0.2는 첫 항이 같은 줄에 이어진다(`제2조(정의) ① …`). 조 번호·제목·항 내용은 같다.
- 별표·서식은 v0.3에서 따로 받았다(§2.2).

### 2.2 v0.3 공식 API 대조와 별표 수집

| 항목 | 내용 |
|---|---|
| API | 공공데이터포털 "법제처_국가법령정보 공유서비스"(데이터 15000115), `https://apis.data.go.kr/1170000/law/lawSearchList.do` |
| 인증 | 서비스키. 저장소 루트 `.env`의 `open_law_key`·`open_law_endpoint`로만 읽고 **파일·로그에 남기지 않음** |
| 제공 기능 | **목록 검색만** 있다. `target=law`(법령 목록), `target=licbyl`(별표·서식 목록). 본문 조회 기능(`lawService.do` 등)은 이 게이트웨이에 없음(응답 코드 12) |
| 필수 인자 | `serviceKey`, `target`, `query`, `pageNo`(빠지면 코드 04), `numOfRows` |

| 단계 | 요청 | 얻는 값 |
|---|---|---|
| 1 | `target=law&query=<법령명>` → 법령명 완전 일치·현행 1건 | 법령일련번호, 법령ID, 시행일자, 공포일자, 소관부처명 → v0.2 행과 대조 |
| 2 | v0.2와 같은 본문 페이지의 `<a name="byl">` 별표 목록 | 별표 표기(`[별표 N]`, `[별지 제N호서식]`), 별표일련번호, PDF 파일 번호 |
| 3 | `target=licbyl&query=<별표 제목>` → 별표일련번호가 같은 항목 | 별표번호(`000100` → `table_no` `0001`, `table_branch` `00`), 별표종류, 관련 법령일련번호 확인 |
| 4 | `GET https://www.law.go.kr/LSW/flDownload.do?flSeq=<n>` | 별표 PDF → `_별표원본/<lsiSeq>/<별표일련번호>.pdf` |
| 5 | PyMuPDF로 글자 위치를 읽어 줄 단위 텍스트 | `text` |

- 대조 결과: 18문서 모두 법령일련번호·시행일·소관부처가 v0.2 행과 같다.
- `licbyl`은 별표 **제목**으로만 찾는다(법령명으로는 0건). 그래서 별표 목록은 본문 페이지에서 얻고, API는 확인용으로 쓴다.
- 19개 중 **17개는 API 목록과 일치**(`api_verified: true`). 장애인기업활동 촉진법 시행령 서식 2개는 API 검색에 나오지 않아 표기에서 번호를 땄다(`api_verified: false`).
- 일부 PDF는 텍스트를 그냥 뽑으면 띄어쓰기가 사라진다(`■중소기업기술혁신촉진법시행령[별표1]`). 글자 사이 간격이 글자 크기의 0.18배보다 크면 공백을 넣어 되살렸다.
- 공공데이터포털 응답의 `법령상세링크`에는 다른 사용자의 인증값이 들어 있어 쓰지 않았다.
- 요청 사이 1초 대기. 연결 시간 초과는 4번까지 다시 시도한다.

### 3.3 인용 집계 방법 (정규식)

도구: `python tools/law_citation_count.py` → `data/법령/인용집계.csv` (출처, 법령명, 인용 공고 수). §3.1의 수치가 이 결과다.

**1) 보는 범위**

| 출처 | 대상 문서 | 보는 필드 |
|---|---|---|
| 기업마당 | 공고 1,294건 | `eligibility_criteria_text`, `summary`, `target_group_text`, `notes`, `bullet_blocks`, `intro_lines` |
| K-Startup | 공고 3,819건 | `eligibility_text`, `support_details`, `announcement_body`, `evaluation_criteria` |
| 나라장터 (참고) | 모집 중 용역 공고문 4,017건 | "입찰참가자격" 또는 "참가자격" 제목부터 **3,000자** |

**2) 법령 이름을 찾는 패턴**

| 패턴 | 정규식 | 잡는 예 |
|---|---|---|
| 낫표 인용 | `[「｢『]\s*([^」｣』\n]{2,60}?)\s*[」｣』]` | `「중소기업기본법」`, `｢여성기업지원에 관한 법률｣` |
| 낫표 없는 인용 | `([가-힣·ㆍ\s]{2,40}?(?:법\|법률\|기본법\|특별법\|시행령\|시행규칙))\s*제\s*\d+\s*조` | `중소기업기본법 제2조`, `소상공인기본법 제3조` |

**3) 정리 규칙**
- 찾은 이름의 끝이 `법`, `법률`, `시행령`, `시행규칙`, `규칙`, `규정`, `고시`, `지침`, `조례` 중 하나일 때만 법령으로 인정한다. 길이는 45자 이하.
- 이름 뒤에 붙은 `제N조…`는 지우고, 연속 공백은 하나로, `ㆍ`는 `·`로 바꾼다.
- **한 공고 안에서 같은 법령은 1회만 센다.** 숫자는 "그 법령을 인용한 공고 수"다.

**4) 수집 목록에 옮길 때 사람이 한 일**
- 띄어쓰기·별칭 변형을 하나로 합산했다. 예: 기업마당 중소기업기본법 128 = `중소기업기본법` 117 + `중소기업 기본법` 7 + `중소기업기본법 시행령` 4. K-Startup 중소기업창업 지원법 98 = `중소기업창업 지원법` 71 + `중소기업창업지원법` 21 + `중소기업창업지원법 시행령` 6.
- 신청자 유형 정의 법령인지, 준수·증빙·업종 등록 맥락인지는 법령명과 인용 문장을 보고 사람이 판단했다(§3.2).

**5) 한계**
- **놓치는 인용:** 낫표도 조 번호도 없는 표기(예: "중소기업창업 지원법에 따른 창업기업")는 1)의 패턴으로 잡히지 않는다. 그래서 실제 인용 수는 표보다 많다.
- **잘못 잡히는 이름:** `조 및 같은 법 시행령`, `법률`처럼 앞말이 잘린 조각이 일부 섞인다. 집계 파일에는 그대로 두고, 수집 목록을 정할 때 사람이 걸렀다.
- **자격이 아닌 인용도 센다:** "소상공인기본법 제3조에 따라 공고합니다"처럼 사업 근거로 인용한 경우도 포함된다.
- 기업마당 첨부 공고문은 저장소에 없어 API 문구만 셌다.

공고 ↔ 조문 연결(§5.4)은 이 집계와 별도로, 수집한 26개 법령의 이름·별칭만 찾는 더 좁은 패턴을 쓴다(`tools/law_citation_map.py`).

### 3.4 v0.2 추가 기준: 법령 인용은 적지만 자격 용어로 자주 나오는 유형

v0.1은 "법령을 인용한 공고"로 골랐기 때문에, 공고가 법령명 없이 **용어만** 쓰는 신청자 유형은 정의 원문이 없었다. 정리층 공고(`data/cleaned/20261124/`, 5,113건)에서 용어가 나온 공고 수를 세어 정의 법령을 추가했다.

| 용어 | 공고 수 | 정의 법령 (추가) | 정의 위치 |
|---|---:|---|---|
| 청년 | 725 | 청년기본법 | 제3조 (19~34세. 공고별 나이 기준이 우선) |
| 장애인기업 | 76 | 장애인기업활동 촉진법 | 제2조, 시행령 제2조 |
| 이노비즈 / 메인비즈 | 67 / 47 | 중소기업 기술혁신 촉진법 | 제15조, 제15조의3 |
| 어업인 | 56 | 수산업ㆍ어촌 발전 기본법 | 제3조, 시행령 제3조 |
| 농업인 | 47 | 농업ㆍ농촌 및 식품산업 기본법 | 제3조, 시행령 제3조 |
| 마을기업 | 47 | 마을기업 육성 및 지원에 관한 법률 | 제2조 |
| 연구소기업 | 37 | 연구개발특구의 육성에 관한 특별법 | 제9조의3 |
| 자활기업 | 31 | 국민기초생활 보장법 | 제18조 |
| 중소기업협동조합 | 24 | 중소기업협동조합법 | 제2조, 제3조 |

`cited_by`는 v0.1과 같은 규칙(법령명·약칭, 뒤 40자 안의 `제N조(의M)`)으로 정리층 공고의 청크·자격·본문·지원·평가 문구에서 찾았다. 시행령은 `<법령명> 시행령`으로만 찾고, 법률 이름 뒤에 `시행`이 이어지면 법률 인용으로 세지 않는다. `같은 법`·`동법` 처리는 하지 않았다.

## 5. 스키마

### 5.1 `조문.jsonl` (2,369행)

**행 구성:** 법령마다 맨 앞에 `level=law`인 **"법령 전체" 행 1개**(44행)를 두고, 그 뒤에 `level=article`인 조문 행(2,325행)이 온다. v0.2 추가 18문서는 파일 뒤쪽에 있다.

```json
{"doc_name": "중소기업창업 지원법", "article_no": null, "article_title": "(법령 전체)", "text": "", "level": "law", "cited_by": ["BIZINFO:…", "KSTARTUP:179828", …]}
{"doc_name": "중소기업창업 지원법", "article_no": "1", "article_title": "목적", "text": "제1조(목적) …", "level": "article", "cited_by": []}
```

기본 키: `doc_id` + `article_no` (법령 전체 행은 `article_no`가 null, 중복 0건)

| 필드 | 타입 | 설명 | 예시 |
|---|---|---|---|
| `doc_name` | string | 법령명 | `중소기업기본법` |
| `doc_kind` | string | 법률 / 대통령령 | `법률` |
| `doc_id` | string | 법제처 법령일련번호 (판 단위 식별자) | `281989` |
| `effective` | string | 시행일 `YYYYMMDD` | `20260701` |
| `org` | string | 소관부처 (복수면 쉼표) | `중소벤처기업부` |
| `source` | string | 출처 식별 경로. 주소로는 열리지 않음(404). 원문 주소는 `https://www.law.go.kr/lsInfoP.do?lsiSeq={doc_id}` | `law.go.kr/law/281989` |
| `chapter` | string 또는 null | 소속 장·절 제목 (장 구분이 없는 조문 807개는 null) | `제1장 총칙` |
| `article_no` | string 또는 null | 조 번호, 가지 조는 `의N`. 법령 전체 행은 null | `2`, `7의4` |
| `article_title` | string 또는 null | 조 제목 (조문 행 118개 null, 주로 삭제 조). 법령 전체 행은 `(법령 전체)` | `중소기업자의 범위` |
| `text` | string | 조·항·호·목을 줄바꿈으로 합친 원문 | `제2조(중소기업자의 범위) ①…` |
| `deleted` | boolean | 삭제된 조 | `false` (삭제 115개) |
| `priority` | string | 수집 우선순위 | `P1` (1,456) / `P2` (869) |
| `why` | string | 선택 이유 | `중소기업 정의와 규모 기준…` |
| `level` | string | `law` 법령 전체 행 / `article` 조문 행 | `article` |
| `cited_by` | string[] | 이 행을 인용한 공고 ID 목록 (없으면 빈 리스트). **조문 행은 조 번호까지 인용한 공고, 법령 전체 행은 법령명만 인용한 공고** | `["BIZINFO:PBLN_000000000128083", "KSTARTUP:179489"]` |

`text`·`deleted`·`chapter` 등은 조문 행 기준 설명이며, 법령 전체 행은 `text`가 빈 문자열이다.

**`cited_by` 현황**

| 행 | 공고가 인용한 행 | 공고 ID 수 | 해석 |
|---|---:|---:|---|
| 조문 (`level=article`) | 60개 (v0.1 36 + v0.2 24) | 430 (383 + 47) | 근거 조문이 명확. 판정 근거로 바로 사용 |
| 법령 전체 (`level=law`) | 27개 (v0.1 15 + v0.2 12) | 210 (160 + 50) | 어느 조인지 공고에 없음. 근거로 쓰려면 사람이 조를 확인 |

v0.2 추가분에서 조 단위 인용이 많은 조문: 중소기업협동조합법 제3조 8건, 수산업ㆍ어촌 발전 기본법 제3조 7건, 중소기업 기술혁신 촉진법 제2조·농업ㆍ농촌 및 식품산업 기본법 제3조·국민기초생활 보장법 제18조 각 3건. 중소기업 기술혁신 촉진법 "제42조" 인용 1건은 현행 법률에 없는 조라 연결하지 않았다(옛 판 인용으로 추정, 미확인).

법령명만 인용한 공고는 중소기업창업 지원법 51건, 중소기업기본법 47건, 벤처기업육성에 관한 특별법 13건 순으로 많다. 이 공고들을 모든 조문에 넣지 않는 이유는, 그러면 과태료 조항 같은 무관한 조문까지 근거로 보이기 때문이다. 제1조(목적)에 넣지 않는 이유는 실제로 제1조를 인용한 공고와 구분되지 않기 때문이다.

`tools/law_subset.py`를 다시 돌리면 `level`·`cited_by`와 법령 전체 행이 빠지므로 `tools/law_citation_map.py`를 이어서 실행한다. `law_citation_map.py`는 여러 번 실행해도 법령 전체 행이 중복되지 않는다.

본문 길이: 합계 948,405자, 중앙값 294자, 최대 3,594자. (v0.1 26문서만: 534,404자)

v0.2 추가분은 `조문_인용.csv`·`조문별_인용요약.csv`(§5.4)에 아직 반영하지 않았다. `cited_by` 열에만 있다.

### 5.4 공고 ↔ 조문 연결 (`조문_인용.csv`, `조문별_인용요약.csv`)

공고 문구에서 수집한 26개 법령의 인용을 찾아 공고 ID와 조문을 잇는다. 기업마당은 API 문구(자격·대상·요약·항목·비고), K-Startup은 자격·지원내용·본문·평가 문구를 본다. **기업마당 첨부 공고문은 저장소에 없어 포함하지 않았다.**

`조문_인용.csv` (543행, 인용 1건 = 1행)

| 필드 | 설명 | 예시 |
|---|---|---|
| `notice_id` | 공고 ID (`BIZINFO:…`, `KSTARTUP:…`) | `BIZINFO:PBLN_000000000128083` |
| `source_system` | 출처 | `BIZINFO` |
| `title` | 공고명 | |
| `field` | 인용이 나온 필드 | `eligibility_criteria_text` |
| `law_name` | 수집 법령명 (별칭을 정식 명칭으로 맞춤) | `중소기업기본법` |
| `article_no` | 조 번호. 조 없이 법령명만 쓰면 빈 값 | `2` |
| `article_title` | 조 제목 | `중소기업자의 범위` |
| `link_level` | `article` 조 단위 / `law` 법령 단위 | `article` |

| `evidence` | 인용 앞뒤 원문 | `「중소기업기본법」 제2조에 따른 중소기업으로…` |

`조문별_인용요약.csv` (조문 1개 = 1행): `law_name`, `article_no`(법령 단위면 `(법령 전체)`), `article_title`, `article_found`, `notice_count`, `bizinfo_count`, `kstartup_count`, `notices`(한 줄에 `공고명 [공고 ID]`, 셀 안 줄바꿈), `notice_ids`(`;`로 구분)

**연결 규칙**
- 별칭과 띄어쓰기를 맞춘다: `중소기업창업지원법`·`중소기업 창업 지원법` → `중소기업창업 지원법`, `판로지원법` → 판로지원법 정식 명칭, `벤처기업육성에 관한 특별조치법`(옛 이름) → 현행 특별법.
- `같은 법 시행령`, `동법`은 바로 앞에 인용한 수집 법령으로 본다. 사이에 수집하지 않은 법령(예: 「물환경보전법」)이 끼면 연결하지 않는다.
- 법령명 뒤 40자 안의 `제N조(의M)`를 조 번호로 본다. 항·호까지는 나누지 않는다.
- 한 공고 안의 같은 법령·조는 한 번만 센다.

창업지원법 제25조는 "신산업 창업 분야는 업력 10년까지"라는 **업력 예외**의 근거로 쓰여, 업력 조건 판정에 직접 영향을 준다.

**주의:** 인용이 곧 자격 조건은 아니다. 예를 들어 `소상공인기본법 제3조`(정부와 지방자치단체의 책무)는 "제3조에 따라 사업을 공고합니다"처럼 **사업 근거**로 인용된 것이다. 정규식 추출이라 표기가 특이한 인용은 놓칠 수 있다.

## 10. 한계

- 공공데이터포털 법제처 API는 **목록만** 준다. 조문 본문과 별표 PDF는 국가법령정보센터에서 받는다. 원본 HTML은 저장하지 않았으므로 재현은 `tools/law_web_collector.py`, `tools/law_api_collector.py`를 다시 실행한다(그 시점 현행본을 받음, 별표 PDF는 `_별표원본/`에 있으면 다시 받지 않음).
- v0.3 별표 텍스트는 PDF에서 뽑아 **표의 칸 구분이 없다.** 숫자 기준으로 쓰려면 PDF를 보고 옮겨야 한다.
- 장애인기업활동 촉진법 시행령 서식 2개는 API 목록에서 확인하지 못했다(`api_verified: false`).
- v0.2·v0.3 추가분(18문서, 조문 1,039, 별표 19)은 2026-11-26에 Aura에 MERGE 적재했다(노드 1,076·관계 1,058, 같은 ID 기존 노드 0, V14 = 0). Aura 합계는 `ExternalLaw` 44, `LawArticle` 2,325, `LawAppendix` 59, `PART_OF` 2,384. 같은 날 추가 법령의 정의 조항 10개를 `Definition`으로 만들어 `CITES_LAW`로 조문에 이었다(`tools/graphrag/concepts_laws.py`의 `LAW_DEFS_V03`). 기존 개념 4개(장애인기업·이노비즈·메인비즈·청년)에 더해, 개념이 없던 6개(마을기업·자활기업·연구소기업은 인증, 어업인·농업인·중소기업협동조합은 신청자 유형)를 새로 만들어 10개 모두 `DEFINED_BY`로 이었다. 이어서 v0.2 법령 조문으로 소상공인·중견기업·벤처기업·여성기업·사회적기업·협동조합·1인 창조기업 정의 7개를 더해(`LAW_DEFS_V02`) `Definition`은 23개, `DEFINED_BY`는 21개가 됐다.
- **현행본 1개 판만** 있다. 공고일 기준으로 다른 판이 적용되는 경우(개정 직후 공고)는 판단할 수 없다.
- **별표의 표는 괘선 문자 텍스트**다. 업종별 매출액 기준을 판정 규칙으로 쓰려면 행 단위로 옮기는 작업이 필요하다.
- 별표 제목에 HTML 엔티티(`&lt;`, `&gt;`)가 남아 있는 경우가 있다.
- `소상공인 보호 및 지원에 관한 법률`은 정의 규정이 소상공인기본법으로 옮겨진 뒤의 현행본이라, 옛 공고가 인용한 정의 조항과 다를 수 있다(미확인).
- 인용 집계는 정규식 근사치이며, 기업마당 첨부 원문은 이 저장소에 없어 온톨로지 설계서 v0.2의 집계를 참고로만 썼다.
- `중소기업 범위 및 확인에 관한 규정`(중소기업 확인서 기준 고시)은 기업마당·K-Startup 인용이 없어 제외했다. "중소기업확인서 보유" 조건 판정에 필요해지면 `data/법령/`에서 바로 추가할 수 있다.
- **판정에 필요한데 아직 없는 자료가 있다.**
  - **한국표준산업분류(KSIC) 코드표:** 중소기업 규모 기준(시행령 별표 1)이 업종을 분류 코드로 나누므로, 사용자 업종을 코드에 맞추지 못하면 별표 숫자를 쓸 수 없다. 온톨로지 INDUSTRY 개념과도 같은 표다.
  - **신산업 창업 분야 고시(중소벤처기업부):** 중소기업창업 지원법 제25조의 "신산업 창업 분야는 업력 10년까지" 예외를 판정하려면 분야 목록이 필요하다(K-Startup 19건 인용).
- 실제 판정은 대부분 공고가 묻는 **확인서**(중소기업확인서, 창업기업확인서, 벤처기업확인서, 여성기업확인서) 보유 여부로 하고, 법령 조문·별표는 판정 근거 설명과 "확인서가 없지만 기준상 해당할 수 있음" 안내에 쓰는 것을 전제로 한다.
