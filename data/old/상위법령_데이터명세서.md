## 3. `상위법령_변환/구조화/<문서ID>.json`

사규 변환본과 키가 같습니다. 차이는 `doc`에 법령 전용 필드가 더 있다는 점입니다.

```json
{
  "doc": { ... },
  "preamble": [],
  "chapters": [ ... ],
  "articles": [ ... ],
  "addenda": [ ... ],
  "external_refs": [ ... ],
  "internal_refs": [ ... ],
  "unresolved_refs": [ ... ],
  "exception_sentences": [ ... ],
  "delegation_candidates": [ ... ],
  "stats": { "chars": 49766, "has_articles": true }
}
```

### 3.1 `doc`

| 필드 | 형식 | 설명 | 예시 |
|---|---|---|---|
| `id` | str | 문서 ID. 정식 명칭에서 공백 제거. 사규 ID와 겹치지 않음(확인함) | `은행법` |
| `title` | str | 법제처 정식 명칭 | `은행법` |
| `doc_type` | str | 법령 종류 (법률, 대통령령, 총리령, ○○부령, 고시, 세칙 …) | `법률` |
| `level` | int | 위계. 1 법률, 2 시행령, 3 시행규칙·부령, 4 고시, 5 세칙 | `1` |
| `date` | str | 시행일 (YYYY-MM-DD) | `2026-07-01` |
| `promulgated` | str | 공포일(법령) 또는 발령일(행정규칙) | `2025-12-30` |
| `action` | str | 최근 제·개정 구분 | `일부개정` |
| `ministry` | str | 소관 부처 | `금융위원회` |
| `law_id` | str | 법제처 법령ID 또는 행정규칙ID (버전이 바뀌어도 유지되는 ID) | `001549` |
| `source` | str | 고정값 | `법제처 국가법령정보센터` |
| `api` | str | 수집 API | `law.go.kr/DRF/law` 또는 `.../admrul` |
| `file` | str | `상위법령_수집원본/원본/` 안의 원본 파일명 | `law_282001.json` |
| `priority` | str\|null | 팀 목록 우선순위. 시행령·시행규칙은 모법의 우선순위를 물려받음 | `1순위` |
| `why` | str\|null | 수집 이유 (`팀 수집 목록`, `IBK 규정이 인용`, `○○법의 시행령` 등) | `팀 수집 목록` |
| `format` | str | 고정값 | `api-json` |

> ⚠ `level`은 설계서 §4.1의 `level_rank`(법률·시행령 1, 감독규정 2, 정관 3, 규정 4, 세칙·지침 5)와 **척도가 다릅니다.** 적재 전에 하나로 합쳐야 합니다.

### 3.2 `chapters[]`

| 필드 | 설명 | 예시 |
|---|---|---|
| `no` | 편·장·절 번호 | `제1장` |
| `title` | 제목 | `총칙` |
| `kind` | `편` / `장` / `절` / `관` | `장` |
| `part` | 소속 편 (없으면 null) | `null` |

### 3.3 `articles[]`

| 필드 | 설명 | 예시 |
|---|---|---|
| `id` | 조문 ID `<문서ID>#<조>`. 편마다 조 번호가 다시 시작하는 문서는 `#제1편-제1조` | `은행법#제34조` |
| `no` | 조 번호. 감독규정의 편-조 번호는 그대로 (`제1-2조의2`) | `제34조` |
| `title` | 조 제목 | `건전경영의 지도` |
| `part`, `chapter` | 소속 편·장 | `null`, `제5장` |
| `deleted` | 삭제되었거나 다른 조로 옮겨져 번호만 남은 조 | `false` |
| `head_text` | 조 제목 뒤 첫 문장 | |
| `paragraphs[]` | 항 목록: `{no: "①", text, items: [{no: "1", text, subitems: [{no: "가", text}]}]}` | |
| `text` | 항·호·목을 합친 본문 | |

### 3.4 참조·후보 목록

| 키 | 필드 | 설명 |
|---|---|---|
| `external_refs` | `from`, `target_name`, (`target_article`, `paragraph`) | 「」로 인용한 다른 법령. 조 번호가 붙어 있으면 `target_article` |
| `internal_refs` | `from`, `to`, `paragraph`, `item` | 같은 문서 안의 조문 참조 (대상 조문이 존재함을 확인함) |
| `unresolved_refs` | `from`, `to`, `paragraph`, `item`, `context` | 대상을 확정하지 못한 참조. 대부분 `법 제2조`, `영 제3조`처럼 **모법·시행령을 가리키는 표현** |
| `exception_sentences` | `article`, `text` | "다만"이 들어간 문장 (단서 후보) |
| `delegation_candidates` | `article`, `text` | "정한다", "정하는 바" 등이 들어간 문장 (위임 후보) |

`addenda`에는 **가장 최근 부칙 1건**만 넣었습니다(전체 부칙은 수천 줄인 법률이 있음).

## 5. 사규와의 연결

| 항목 | 값 |
|---|---|
| 사규 → 코퍼스 밖 외부 참조 | 718건 |
| 그중 이 데이터의 문서로 연결되는 참조 | **463건 (64%)**, 대상 문서 118개 |
| 조 번호까지 적은 인용 | 146건 (20%) — 고유 조문 121개 |
| 법 이름만 적은 인용 | 572건 (80%) — 해당 조문은 질의 시 검색으로 찾아야 함 |
| 연결 안 되는 나머지 | 대부분 ALIO에 없는 비공개 내규 (여신업무취급세칙, 업무분장규정 등)와 위 가이드라인 3건 |

사규의 인용 표기는 약칭·띄어쓰기가 섞여 있습니다(예: `금소법`, `금융소비자보호법`). 연결할 때 공백·가운뎃점을 지우고 약칭을 정식 명칭으로 바꿔야 합니다. 약칭 대응은 `팀_법령수집목록.txt`의 셋째 열과 `data/law_collection_list.csv`(팀 목록)의 "문서 내 표기 변형" 열을 참고하세요.

## 6. 알려진 한계

1. **현행본만 있음** — 사규는 2005~2026년 개정본이 섞여 있어, 오래된 사규를 현행 법령과 비교하면 위반처럼 보일 수 있습니다. 판정 시 기준 시점을 표시해야 합니다.
2. **단서·위임 후보의 문장 경계가 거칢** — 사규 변환기와 같은 규칙("다." 기준 분리)을 써서, 정의 목록이 긴 조문(예: 은행법 제2조)은 여러 호가 한 문장으로 묶입니다. 후보로만 쓰고 LLM·검수로 정제해야 합니다.
3. **`unresolved_refs`의 상당수는 규칙으로 풀 수 있음** — 시행령 안의 `법 제N조`는 모법, `영 제N조`는 같은 계열 시행령입니다. 적재 단계에서 이 규칙으로 법 → 시행령 위임 관계를 이을 수 있습니다.
4. **본문이 문자열 하나로 오는 행정규칙** (예: 금융투자업규정) — 조·항 단위로는 나뉘지만 호(1., 2.)가 항 본문에 붙어 있을 수 있습니다.
5. **별표·서식** — 별표(금액표 등)는 수집하지 않았습니다. 본문에 "별표 2와 같다"로만 남습니다.

## 7. 다시 만드는 방법

```bash
# 1) 수집 (법제처 OPEN API 인증값 필요, 코드·파일에 저장하지 말 것)
export LAW_OC=<인증값>          # PowerShell: $env:LAW_OC = "<인증값>"
python tools/upper_docs_collector.py            # → data/상위법령_수집원본/
python tools/upper_docs_collector.py --dry-run  # 무엇을 받을지만 출력

# 2) 변환 (인증값 불필요, 원본만 있으면 됨)
python tools/convert_law.py                     # → data/상위법령_변환/
```

- 조문 구조화와 참조 추출은 `tools/convert_ibk.py`의 `parse_regulation`을 그대로 사용합니다. `convert_ibk.py` 파일은 수정하지 않았고, `convert_law.py` 안에서만 감독규정의 `제1-1조` 형식을 인식하도록 조 번호 패턴을 넓혔습니다.
- 수집 목록을 바꾸려면 `data/팀_법령수집목록.txt`를 고칩니다. 형식: `우선순위 | 법제처 정식 명칭 | 사규 내 표기(참고)`
- 개칭된 법령은 새 이름으로 적었습니다: `국가유산수리 등에 관한 법률`(구 문화재수리법), `벤처기업육성에 관한 특별법`(구 특별조치법), `전기통신금융사기 피해 방지 및 피해자산 환급에 관한 특별법`(구 피해금 환급).
