# SQL–벡터 RAG 베이스라인 측정 방법과 KPI 산정 근거 (v0.1)

> 지원각 · 근거 it(2팀) · 2026-11-25 · 강사 피드백 ⑦ "SQL–Vector RAG baseline 측정방법 정함, KPI 산정 근거 정의함"에 대응
> 이 문서는 **측정 방법과 산정 근거**를 정한다. KPI 목표값은 베이스라인을 먼저 잰 뒤 중간 발표 전 1회 조정해 확정하며(KPI_DRAFT §10), 이 문서는 목표값을 새로 정하지 않는다. "현재 값"은 2026-11-25까지 코드를 실행해 센 값이고, 측정하지 못한 것은 "미측정"으로 적었다.

## 1. 요약

| 항목 | 내용 |
|---|---|
| 무엇과 무엇을 비교하나 | **A** SQL 필터, **A2** SQL + 계층 테이블, **B** 벡터 RAG(검색 + 모델 판정), **C** 제안(그래프 확장 + 규칙 평가기). 같은 스냅샷·같은 사전·같은 정답셋으로 질문 유형별로 비교 |
| 어떻게 재나 | ① 자동 비교셋: 가상 프로필 300개 × 모집 중 공고(구조 조건 한정, 구현 완료) ② 정답셋: 공고 30건 × 프로필 5개 = 150쌍과 유형별 질문 세트(사람 라벨, **아직 0건**) |
| 현재 값 | A2와 C의 구조 조건 판정이 **완전히 일치**(불일치 0, 프로필 300개 × 공고 1,452건). 평가 시간은 C가 프로필당 약 34ms, A2(SQL)가 약 2.3ms(2026-11-27 재측정, 둘 다 같은 프로세스). B는 **미구현**(임베딩 모델·판정 모델 미정, 검색은 BM25만) |
| 막힌 것 | 정답 라벨 0건, 벡터 RAG 모델 미정(D-10), 법령·묶음 사전 검수 전 |
| 해석 원칙 | 어느 구성도 미리 이긴다고 쓰지 않는다. 신뢰구간이 겹치면 우열을 주장하지 않고, 지는 유형도 보고한다 |

## 2. 비교 구성

| 구성 | 후보 찾기 | 조건 평가 | 계층 확장 | 판정 주체 | 현재 구현 |
|---|---|---|---|---|---|
| **A** SQL 필터 | 정형 필드 일치(지역 이름 문자열, 업력 구간) | 필드 비교(`WHERE`) | 없음(지역은 같은 값만) | SQL | 지역·업력 필터를 SQLite로 구현(`tools/graphrag/build.py`) |
| **A2** SQL + 계층 테이블 | 위와 같음 | 필드 비교 + **폐쇄 테이블**(`closure`, 재귀 CTE 가능) | 시군구→시도→권역·개편 묶음을 테이블로 | SQL + 코드 | 폐쇄 테이블 조인으로 구현. 같은 묶음 사전을 사용 |
| **B** 벡터 RAG | 벡터(dense)·BM25·hybrid top-k 청크 | 없음(문서를 읽고 모델이 판단) | 없음 | **LLM** | BM25 검색만 구현(문자 bigram, 청크 32,930개). 임베딩 모델과 판정 모델은 미정 |
| **C** 제안(그래프 + 규칙) | 구조 필터 + BM25 | 3값 규칙 평가기, 조건 논리 합성 | `WITHIN`·`IS_A` 최대 3 hop, 묶음 | 규칙(코드) | 구조 조건 한정 구현(`tools/graphrag/`). 본문 요건 미연결이라 `ELIGIBLE`을 내지 않음 |

**공정성 규칙(반드시 지킨다)**
1. 같은 공고 스냅샷(`data/cleaned/<날짜>`의 해시를 기록)을 쓴다.
2. A2에도 C와 **같은 코드표·묶음 사전**을 준다. 사전 유무가 아니라 "계층을 테이블로 푸느냐 그래프로 푸느냐"의 차이만 보기 위해서다.
3. 같은 정답셋·같은 프로필·같은 판정 기준(3값, 합성 규칙)을 쓴다.
4. B는 같은 청크를 검색하고 같은 판정 지시문·같은 모델 설정을 쓴다. 생성 온도는 낮게 고정하고 **3회 반복**해 흔들림을 기록한다.
5. 지연은 같은 기기에서 같은 조건(워밍업 제외)으로 잰다. 원격 DB(Aura)는 네트워크가 섞이므로 서버 처리 시간을 따로 적고, 구성 간 지연 비교는 같은 기기에 띄운 DB로 한다. 빈 질의(`RETURN 1`·`SELECT 1`) 왕복으로 질의당 고정 비용도 함께 적는다.
6. 평가셋은 구성을 고르는 데 쓰지 않는다(공고 단위로 dev/final 분리, 4.2).

## 5. 통계 처리와 표본 크기의 한계

- **신뢰구간:** 비율은 Wilson 95% 구간으로 보고한다. 점추정만 쓰지 않는다.
- **0건 관측:** 오탐 0건은 오탐률이 0%라는 뜻이 아니다. 관측 0건일 때 참 오탐률의 95% 상한은 대략 3/n이다(3의 법칙).
- **구성 비교:** 같은 쌍으로 구성을 비교하므로 짝지은 차이(구성 X만 맞은 쌍 − 구성 Y만 맞은 쌍)를 보고, 구간이 0을 포함하면 우열을 주장하지 않는다.

| 정답셋 규모 | 정확도 70% 구간 | 정확도 80% 구간 | 정확도 90% 구간 | 오탐 0건일 때 상한(3/n) |
|---|---|---|---|---|
| 50쌍 | 56~81% (±12%p) | 67~89% (±11%p) | 79~96% (±9%p) | 6.0% |
| 90쌍 | 60~78% (±9%p) | 71~87% (±8%p) | 82~95% (±6%p) | 3.3% |
| 150쌍 | 62~77% (±7%p) | 73~86% (±6%p) | 84~94% (±5%p) | 2.0% |

해석: 파일럿 10건(50쌍)은 구간 반폭이 ±9~12%p라 **정확도를 주장할 수 없고** 가이드·규칙 시험용이다. 30건(150쌍)에서도 구성 간 차이가 약 10%p 이하이면 구분하기 어렵다. 따라서 발표에서는 "A2와 C가 같은 결과"처럼 차이가 없다는 사실과 지는 유형을 있는 그대로 보고한다.

## 6. 절차

1. 스냅샷 고정: `data/cleaned/<날짜>`와 사전 파일의 해시를 기록한다.
2. 합격선·개선 인정 기준을 **결과를 보기 전에** 문서에 적는다(결정 기록표).
3. 정답셋 파일럿(10건) → 가이드 개정 → 나머지 20건 라벨링 → dev/final 분리.
4. 구현 순서: A → A2 → C(구현 완료) → B(임베딩·판정 모델 확정 후).
5. dev로 3회 반복 측정하고 구성별·유형별 결과표를 만든다(행: 질문 유형, 열: A·A2·B·C × N-02·N-03·N-04·E-04·지연).
6. 중간 발표 전 목표를 1회 조정하고 final로 1회 확정 측정한다.
7. 결과표에는 **이기는 유형과 지는 유형을 모두** 싣는다. A2가 C와 같은 결과를 내면 그 사실을 보고하고 주장 범위를 좁힌다.

| 항목 | 값 | 해석 |
|---|---|---|

| 검색(BM25) | 청크 32,930개, 색인 약 4.5초, 질의 약 0.04초 | Recall@5는 정답이 없어 **미측정** |
| N-03 오탐 | `ELIGIBLE`을 내지 않아 오탐 0 | **달성이 아니라 기능 미구현의 결과**다. 본문 요건을 연결하면 다시 재야 한다. 재현율(놓친 `ELIGIBLE`)을 함께 본다 |
| N-01 요건 추출 | 후보 18,021개, 원문 일치 검사 통과 | 정밀도·재현율은 정답이 없어 **미측정** |
| O-07 일치도 | 라벨 0건 | 파일럿 후 측정 |

## 9. 담당·일정(제안)
- 정답셋 파일럿 10건: 라벨러 2명 지정(팀원 3명 중 2명, 나머지 1명은 프로필 배정·점검) → 독립 라벨링 → 일치도 측정(가이드 개정 포함). 라벨링은 `tools/labeler/labeler.html`로 한다.
- 벡터 RAG: 임베딩 모델과 판정 모델 결정(D-10) → B 구현 → 3회 반복 측정.
- 베이스라인 결과표와 KPI 확정은 중간 발표 전 1회로 한다.

## 10. 한계와 미확인
- 정답셋이 아직 없어 **정확도 KPI는 모두 미측정**이다. 자동 비교셋은 두 구현의 일치도일 뿐 규칙의 정당성을 증명하지 않는다.
- 벡터 RAG(B)는 구현하지 않았다. BM25 검색이 대리값이며 임베딩·판정 모델 결과는 다를 수 있다.
- A·A2의 SQL은 우리가 짠 것이라 "충분히 강한 SQL"인지는 평가 전에 팀이 검토해야 한다(공정성).
- 평가용 프로필은 가상이라 실제 사용자 분포를 대표하지 않는다. 공고가 바뀌면 정답이 낡으므로 스냅샷 해시를 기록한다.
- 질문 유형별 문항 수와 dev/final 분리는 제안이며 라벨링 비용에 따라 줄어든다.
- 법령 원문이 부족해 `definition` 유형은 지금 잴 수 없다.
