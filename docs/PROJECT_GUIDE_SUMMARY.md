> 과정명: **LLM 지식 그래프 기반 신뢰형 GraphRAG 구축을 위한 머신러닝 엔지니어 양성 과정**

## 1. 우리 팀(2팀) 한눈에 보기

| 항목 | 내용 |
|---|---|
| 주제 | **기업 규정 준수 여부 검증을 위한 온톨로지 및 Multi-hop 추론 기반 지식 그래프 시스템** |
| STEP 2 목표 | 기업 규정 문서 간 **계층 구조 및 참조 관계** 온톨로지 설계 |
| STEP 3 목표 | 규정 문서 내 **법적 조항 및 예외 사항** 자동 파싱 및 지식 베이스 구축 |
| STEP 4 목표 | 규정 준수 판별을 위한 **Multi-hop 추론 기반 지식 검증 엔진** 구현 |
| STEP 5 목표 | 주제 특화 신뢰형 GraphRAG 서비스 런칭 및 최적화 운영 (전 팀 공통) |
| 최종 시연 포인트 | Compliance(규정 준수) 검증 서비스 정상 시연 |

**필수 성과지표:** 프로젝트 결과물 중 **최소 1건 이상 Hugging Face에 공개**(모델/데모)

## 2. 핵심 기술 스택 (가이드에 명시된 것)

- **그래프 DB:** Neo4j (LPG 모델), Cypher, Neo4j Python Driver, Neo4j GDS 알고리즘(중심성·유사도)
- **LLM/RAG:** LangChain, neo4j-graphrag, 벡터+그래프 하이브리드 검색, Multi-hop 추론, CoT 프롬프트
- **에이전트:** LangGraph 기반 멀티에이전트 (슈퍼바이저·계획·자기성찰), trajectory 평가
- **모델:** PEFT(LoRA) 소형 LLM(SLM) 파인튜닝, 모델 양자화, vLLM 서빙
- **평가/안전:** RAGAS (Faithfulness, Answer Relevance), NeMo Guardrails
- **UI:** Streamlit 등 대화형 웹, 토큰 스트리밍(SSE), 실시간 지식 그래프·추론 과정 시각화
- **운영:** Docker, CI/CD, 클라우드 배포, Langfuse 모니터링·온라인 지속 평가
- **협업:** Git/GitHub

## 3. 단계별 진행 가이드 & 필수 산출물

### STEP 1 · 프로젝트 기획 및 설계
- 팀 빌딩, 주제 구체화, 요구사항 정의·기능 명세, 서비스 아키텍처·기술 스택 설계, WBS·일정 계획
- **산출물:** 기획서(요구사항 명세 포함), WBS, 화면 설계서(IA·와이어프레임)

### STEP 2 · 도메인 분석 및 지식 그래프 온톨로지 설계
- 외부 API·공개 데이터 수집 + EDA·통계 분석으로 도메인 정량 이해
- 비정형 문서에서 핵심 엔티티·관계 추출 → Neo4j LPG 노드/엣지 스키마 정의
- 온톨로지 검증 및 Cypher 쿼리 설계, Git/GitHub 협업 환경 구축
- **산출물:** 도메인 온톨로지 설계서, Neo4j 그래프 스키마 정의서
- **평가 포인트:** 엔티티/관계 추출의 명확성, 온톨로지의 논리적 타당성·정합성, 도메인 요구 부합, 데이터 기반 정량 이해 / 속성·제약조건 명시, Cypher 쿼리 및 인덱스 전략 포함

### STEP 3 · LLM 기반 지식 추출 및 그래프 DB 구축
- LangChain 지식 추출 파이프라인 + 프롬프트 최적화, NER·관계 추출용 CoT 프롬프트
- Neo4j Python Driver로 대용량 S-P-O 트리플 자동 적재
- Entity Resolution으로 중복 제거 및 정합성 검증
- **산출물:** 데이터 적재 스크립트
- **평가 포인트:** 안정적 자동 적재, Entity Resolution 내장, 정합성·예외 처리 로직

### STEP 4 · 하이브리드 검색 GraphRAG 엔진·멀티에이전트·인터페이스
- LangChain·neo4j-graphrag 기반 지식 인덱싱 + 벡터/그래프 하이브리드 검색
- Neo4j GDS 기반 추천, Streamlit 대화형 UI
- 실시간 지식 그래프 시각화 및 LLM 추론 과정 투명성 확보
- 할루시네이션 방지를 위한 검색 결과 재구성 + Multi-hop 추론
- LangGraph 멀티에이전트(슈퍼바이저·계획·자기성찰) **직접** 설계·구현
- **산출물:** GraphRAG 추론 엔진 및 멀티에이전트 오케스트레이션 엔진
- **평가 포인트:** 하이브리드 검색 구현, Multi-hop 기반 답변 신뢰성, 맥락 유지 메모리 관리, LangGraph 멀티에이전트 직접 구현

### STEP 5 · RAGAS 품질 평가 및 시스템 최적화·배포
- RAGAS로 충실도·관련성 정량 평가 및 개선
- PEFT(LoRA)로 도메인 지식 주입 및 SLM 파인튜닝
- vLLM + 양자화 고속 추론 서빙, 클라우드 배포
- NeMo Guardrails 안전성·보안 가드레일
- 실시간 실행 흐름 모니터링, Docker·CI/CD, Langfuse 운영 모니터링·온라인 평가
- **산출물:** 최종 배포 웹 애플리케이션, 성능 평가 보고서
- **성능 평가 보고서에 반드시 포함:**
  - RAGAS 지표(Faithfulness, Answer Relevance 등)
  - 트리플 품질 지표(샘플 정밀도, 온톨로지 스키마 준수율, Entity Resolution 일관성)
  - 데이터 수집·EDA·통계 기반 도메인 인사이트
  - NeMo Guardrails 설계 및 검증 결과
  - LoRA 파인튜닝 **전/후** 성능 비교 분석

> 위 산출물은 **필수**이며, 추가 산출물은 운영 매니저와 협의 후 진행.

## 4. 발표 평가 기준

공통 항목 (중간·최종 모두)
- **기획:** 시장·사용자 요구 분석, 실질적 활용 가능성, 문제·해결방법의 타당성·창의성, 경쟁력·차별화
- **발표역량:** 기획·진행현황의 효과적 전달, 질의응답의 논리적 대응

### 중간 발표 — 구현/기술
- 온톨로지·지식 그래프 스키마 기초 설계 구현
- LangChain/Neo4j Driver로 S-P-O 트리플 자동 추출 및 DB 기초 적재 동작
- 하이브리드 검색·GraphRAG 핵심 동작용 기본 데이터 모델 **시연 가능**
- Neo4j LPG 모델링 기법의 타당성, 프롬프트 엔지니어링·CoT의 기술적 깊이
- Git/GitHub 협업 환경 및 설계 산출물의 논리적 완결성

### 최종 발표 — 구현/기술
- 지식 그래프 → 하이브리드 검색 → 대화형 UI → RAGAS 평가까지 연계된 GraphRAG 완성도
- 데이터 분석·멀티에이전트·GraphRAG가 **하나의 서비스로 통합**
- 팀별 도메인 서비스(2팀: Compliance 검증) 정상 시연
- 실시간 지식 그래프·추론 과정 시각화의 안정적 동작
- 하이브리드 검색 + Multi-hop 추론 설계 완성도
- Neo4j GDS 알고리즘 / 오케스트레이션 알고리즘의 기술적 깊이
- 멀티에이전트 직접 구축 + trajectory(도구 선택·step 성공률) 평가
- LoRA SLM 파인튜닝 + 양자화/vLLM 서빙 최적화
- RAGAS 기반 정량 평가 체계 및 개선 피드백 루프
- NeMo Guardrails 실무적 설계·작동
- Entity Resolution 기반 데이터 정제·그래프 무결성

## 5. 운영 규칙

### 팀 구성
- 주제 선호도(1·2순위), 교과목 성취도, 진로 방향, 성향·역할, 협업 스타일, 갈등 예방을 고려해 배정
- 팀 확정 후에는 특별한 사유(건강·출석 등) 외 **변경 불가**
- 진행 순서: 대주제 확정 → 주제 구체화 → 계획에 따른 진행 → **중간발표 → 최종발표**

### 팀장
- 운영 매니저와의 **주 소통 창구**(일정, 산출물 제출, 지원 요청)
- 1등 상금이 팀장에게 우선 지급되므로 책임감 있는 사람으로 신중히 선정
- 선정 후 팀 대시보드 '팀원 및 역할' 표에서 역할을 '팀장'으로 지정

### 리워드
- 최종 발표 **1등 팀 상금 100만 원** (심사위원 평가, 팀장에게 우선 지급)

### 멘토링
- 팀당 **최대 20시간**(온·오프라인 합산), 오프라인 권장
- 온라인 인정 시간은 오프라인 시간을 넘을 수 없음 (예: 오프 5h + 온 10h → 10h만 인정)
- 팀 단위·1:1 모두 가능 / 멘토는 정답보다 실무 기반 방향 제시, 종합 관리·평가는 강사 담당
- 멘토 역할: 기획 인사이트, 기술 가이드·사례 공유, 일정 관리 팁, 과제 부여·평가, 온라인 Q&A, 취업·이력서·포트폴리오·GitHub 상담

### 수강생이 할 일
- 멘토링 일정은 **팀장이 멘토와 협의** → 디스코드 팀 채널에 공유
- 질문·자료는 멘토링 **전에** 디스코드에 미리 업로드
- 멘토 피드백 반영 내용은 **대시보드 일일 진행 기록**에 기록
- 시작 시간에 맞춰 모여 **증빙 사진**(시작 전·후, 날짜·시간 보이게) 촬영 협조
  - 온라인은 화면 캡처(시계 포함), 개인 멘토링은 사람별로 따로 촬영

### 소통
- 주 소통·자료 공유는 **디스코드 채널**(매니저도 확인 가능). 오픈채팅 등은 최소화
- 이력서 등 개인정보 문서는 디스코드 금지 → 멘토와 1:1(이메일 등)로 전달
