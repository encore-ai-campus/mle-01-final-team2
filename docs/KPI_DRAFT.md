## 0. 읽는 법과 원칙

1. **수업 예시는 출발점이지 우리 목표가 아니다.** 예시 표의 안내("실제 KPI 목표는 프로젝트 특성에 맞춰 설정")를 따라, 지표마다 **그대로 쓰는지·조정하는지·바꾸는지**를 §1에 적었다.
2. **잠정 목표는 측정 전의 가설이다.** 베이스라인(`base` 모델, 벡터 단독 검색)을 먼저 재고, **그 결과를 본 뒤 중간 발표 전에 확정**한다(§9). 아래 수치에는 근거를 달았지만 달성 가능성을 보장하지 않는다.
3. **합격선은 두 개로 쓴다.** 절대 하한과 "기준선 대비 하락 허용폭"(설계서 §9 회귀 게이트). 소형 모델 SFT로 판단 능력이 거의 오르지 않았다는 수업 사례(적용 0/21 → 1/21)가 있으므로, **판단 지표는 낙관하지 않는다.**
4. **안전 지표는 평균이 아니라 건수로 본다.** 비인가 접근 1건, 확정적 징계 표현 1건이 평균에 묻히지 않도록 "0건", "100%"를 목표로 둔다.
5. **표본이 작다는 점을 같이 적는다.** 평가셋이 60문항이면 1문항이 1.7%p다. 이 정도 차이는 해석하지 않는다(설계서 §9).
6. 대상 질문 유형·모드(사원/인사)가 있는 지표는 **모드별로 따로 센다.**

## 1. 수업 예시 KPI의 적용 방안

| 수업 예시 | 예시 목표 | 우리 프로젝트 적용 | 이유 |
|---|---|---|---|
| Task Success Rate | 90% 이상 | **조정** — 판정·근거 조문이 모두 맞아야 성공(§2 Q-01) | 에이전트 작업의 성공 조건을 우리 서비스 기준으로 정의해야 함 |
| Accuracy | 90% 이상 | **조정** — 판정 3분류(위반 가능 / 문제 없음 / 판단 불가) 정확도(Q-02) | 소형 모델·서술형 의무라 90%는 근거가 없음 |
| Precision / Recall / F1 | 85% / 85% / 0.85 | **분리 적용** — ① 지식 추출 ② 조항 후보 검색 ③ 파서 관계로 나눔(§3) | 한 숫자로 합치면 의미가 없음. 인사 모드는 **재현율(누락 방지)** 이 정밀도보다 중요 |
| Latency | 평균 3초 이하 | **바꿈** — 평균이 아니라 **첫 토큰 p95·전체 p95**(P-01·P-02) | Multi-hop + 스트리밍 응답이라 "평균 3초 완료"는 맞지 않음 |
| Error Rate | 2% 이하 | **그대로** | 5xx·타임아웃·빈 응답 기준 |
| RAG Faithfulness | 0.90 이상 | **조정** — 0.85에서 시작(Q-05) | 한국어 판사 신뢰도·소형 판사 문제(설계서 §9). 확정은 측정 후 |
| System Availability | 99% 이상 | **조정** — 시연·평가 기간 기준(P-04) | RunPod는 사용 시에만 구동(NFR-08), Aura Free는 일시중지 가능성(설계서 ADR-2) |
| Cost per Request | $0.01 이하 | **보류** — 산식만 정하고 목표는 GPU·모델 확정 후(P-05) | 모델 크기·GPU가 학원 예산에 따라 결정됨 |
| (없음) | — | **추가** — 근거 인용, 거절, 판단 불가, 검색, 온톨로지, 안전, 모델 비교, 에이전트, 메모리 | 규정 준수 도메인과 필수 요건(LoRA 전후, Guardrails 등)에 필요 |

## 2. 답변 품질 (사원·인사 공통)

평가셋: 설계서 §9의 유형 A/B/C/D + 후속 질문 + 근거 없는 질문 + 범위 밖 질문, **최소 60문항**, 최적화용과 최종 확인용(마지막 1회)을 분리한다.

| ID | 지표 | 정의 / 측정 | 잠정 목표 | 근거·비고 |
|---|---|---|---|---|
| Q-01 | **Task Success Rate** | 정답 질문 중 **판정과 근거 조문 id가 모두 gold와 일치**한 비율. 사원·인사 모드별 | 사원 80% 이상 / 인사 70% 이상 | 인사 모드는 사안→조항 매핑이라 더 어렵다고 보아 낮게 시작. 수업의 "적용" 지표가 낮았던 점 반영 |
| Q-02 | **판정 정확도 (Accuracy)** | 판정 3분류가 gold와 일치한 비율(사원 모드 행동 질문) | 80% 이상 | `판단 불가`를 정답으로 둔 문항 포함. 혼동행렬을 함께 보고 |
| Q-03 | **근거 인용 포함률** | 답변 중 조문 id가 1개 이상 인용된 비율(규칙 판정, 모델 호출 없음) | 95% 이상 | NFR-01. 결정적으로 셀 수 있어 목표를 높게 둠 |
| Q-04 | **인용 조문 일치율** | 인용한 조문 id가 gold 근거에 포함된 비율 | 85% 이상 | 존재하지 않는 조문 인용은 0건을 목표로 별도 집계(환각 인용) |
| Q-05 | **RAGAS Faithfulness** | 답변이 검색 근거에 충실한 정도(0~1). 한국어 `system_prompt` 지정, NaN 별도 확인 | 0.85 이상 | 예시 0.90에서 한 단계 낮춰 시작. **Faithfulness가 높아도 낡은 규정이면 틀리므로 Q-01·Q-04를 같이 봄** |
| Q-06 | **RAGAS Answer Relevancy** | 질문과 답변의 관련성 | 기준선 대비 하락 허용폭 이내 | 합격선은 팀이 정함(설계서 §9). 절대값은 측정 후 |
| Q-07 | **범위 밖·근거 없음 거절률** | 거절해야 할 질문에서 "근거 없음"이라 답한 비율 | 90% 이상 | 규정에 없는 내용을 지어내지 않는 핵심 지표 |
| Q-08 | **과잉 거절률** | 답해야 할 질문을 거절한 비율 | 10% 이하 | Q-07만 올리면 모든 질문을 거절하는 모델이 이김 → 한 쌍으로 본다 |
| Q-09 | **`판단 불가` 적절성** | 정보가 부족한 문항에서 결론 대신 `판단 불가` 또는 되묻기를 한 비율 | 80% 이상 | FR-21. 인사 모드에서 억지 결론을 막는 지표 |
| Q-10 | **후속 질문 정답률** | 맥락 의존 후속 질문(`followup`)의 정답률. 기억 on/off 비교 | 사원 모드 75% 이상, 기억 on이 off보다 높을 것 | 설계서 §8 메모리 |

## 3. 정밀도·재현율·F1 (대상별로 분리)

|---|---|---|---|---|

| E-04 | **조항 후보 검색 Recall@5** | gold 근거 조문 중 상위 5개에 포함된 비율(ID 기반, 모델 호출 없음) | **85% 이상** | 인사 모드는 **누락이 더 위험**하므로 재현율 우선. 예시 85% 유지 |
| E-05 | **조항 후보 Precision@5** | 상위 5개 중 gold 비율 | 50% 이상 | 후보 제시 서비스라 정밀도는 낮게 허용. 사람이 거름 |
| E-06 | **MRR@5** | 정답 조문의 역순위 평균 | 기준선 대비 개선 | 절대값은 측정 후 |

| G-05 | **에이전트 도구 선택 일치율** | 기대 도구 시퀀스와 실제 `tools_used` 일치율, step 성공률 | 80% 이상 | **지표 정의는 자체**(수업에 없음). 불필요 호출 수도 같이 기록 |

## 11. 한계와 미확인

- **모든 목표값은 측정 전 추정이다.** 특히 Q-01·E-01·G-02는 소형 모델 품질에 크게 좌우되며, 모델 크기·GPU가 미정이다.
- 인사 모드 평가셋은 **가상 사안**으로 만들며 실제 직원 사례를 쓰지 않는다. 가상 사안의 난이도가 실제를 대표하지 않을 수 있다.
- RAGAS는 영어 지시문 기반이라 한국어에서 점수가 흔들릴 수 있고, 수업의 판사는 외부 API였다. **자체 호스팅 소형 판사의 신뢰도는 수업에 없어** M-07로 직접 확인해야 한다.
- 에이전트 지표(G-05)와 법령·사규 연결률(O-01)의 정의는 우리가 정한 것이다.
- Aura Free·RunPod의 한도와 가용성은 확인하지 않았다(P-04, O-08).
- 이 문서는 법적 판단·징계 결정의 정확도를 보증하지 않는다. 서비스는 검토 보조 도구다.
