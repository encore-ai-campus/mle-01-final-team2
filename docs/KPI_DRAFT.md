## 0. 읽는 법과 원칙

1. **수업 예시는 출발점이지 우리 목표가 아니다.** 지표마다 그대로 쓰는지·조정하는지·바꾸는지를 §1에 적었다.
2. **목표는 측정 전의 가설이다.** 베이스라인(SQL 필터, 벡터 단독 검색, `base` 모델)을 먼저 재고 **그 결과를 본 뒤 중간 발표 전에 1회 조정해 확정**한다(§10). 확정 전에는 문서·발표에 **"잠정"** 을 붙인다. 이전 주제에서 쓰던 출발값은 참고로만 적었다.
3. **합격선은 두 개로 쓴다.** 절대 하한과 "기준선 대비 하락 허용폭"(기초 설계서 §9 회귀 게이트). 소형 모델 SFT로 판단 능력이 거의 오르지 않았다는 수업 사례(이전 문서 승계, 재확인 필요)가 있으므로 **판단 지표는 낙관하지 않는다.**
4. **안전 지표는 평균이 아니라 건수로 본다.** "신청 가능" 오탐 1건, 선정·수혜를 시사하는 표현 1건, 권한 우회 1건이 평균에 묻히지 않도록 "0건", "100%"를 목표로 둔다.
5. **표본이 작다는 점을 같이 적는다.** 사전 확인 표본은 15건(비무작위, 한 포털의 하루치)이고, 평가셋이 60문항이면 1문항이 1.7%p다. 이 정도 차이는 해석하지 않는다. 요건 라벨 표본은 30건 이상을 제안했으나 아직 만들지 않았다.
6. **판정 평가는 질문 유형별로 따로 센다.** 유형은 기초 설계서 §9와 같다(`filter`, `hierarchy`, `definition`, `explanation`, `relation`, `insufficient`, `out_of_scope`, `pii_input`).
7. **판정은 규칙 평가기(코드)가 하므로 판사 모델로 재지 않는다.** 판정·계층 확장은 정답 라벨과 비교하고, LLM 판사는 설명문 평가에만 쓴다.

### 0.1 핵심 지표와 평가 우선순위

지표가 많아 모두 같은 무게로 보면 핵심이 흐려지므로 4개 층으로 나눈다.

| 층 | 의미 | 지표 | 목표를 정하는 방식 |
|---|---|---|---|
| **0. 게이트**(필수 준수) | 하나라도 어기면 시연·배포하지 않고 어떤 실험 결과도 "개선"으로 인정하지 않는다. 건수로 본다 | S-01 비인가 접근, S-02 감사 로그, S-04 확정 표현, S-06 개인정보 비저장, S-07 데이터 격리, **N-03 "신청 가능" 오탐**, **N-05 출처·수집 시각 표시**, S-09 Unauthorized Retrieval Rate, S-10 Embedding Reconstruction Risk, S-11 Policy Violation Rate | 베이스라인과 무관하게 **100% 또는 0건**(S-10은 §0.2). 기획 보고서 §4.4의 MR-N1~N5와 연결 |
| **1. 핵심 12개** | 발표와 판단의 중심. 이 중 **표준 지표 세트 9개**(§0.2)는 모든 비교 실험에서 함께 잰다 | Q-01 Task Success, **N-02 판정 일치율**, Q-04 인용 근거 일치율, Q-05 Faithfulness, Q-09 확인 필요·판단 불가 적절성, **Q-11 Evidence Coverage**, **N-01 요건 추출 F1**, **N-04 계층 확장 Recall**, E-04 후보 검색 Recall@5, **N-07 GraphRAG vs SQL**, P-01 첫 토큰 지연 p95, P-05 GPU Cost | 베이스라인 측정 후 중간 발표 전 1회 조정해 확정(§10). P-05는 측정 필수이고 목표는 GPU·모델 확정 후 |
| **2. 보조** | 원인 분석과 품질 보강 | 위에 없는 Q·E·G·O·M 지표, S-03·S-05·S-08, N-06, P-08·P-09 | 측정·보고하며 목표는 참고값 |
| **3. 보고용·후순위** | 목표를 두지 않는다 | P-06 goodput, E-06 MRR | 측정값만 기록 |

**측정 순서:** ① 요건 라벨 표본을 만들고 두 사람이 따로 정규화해 일치도(O-07)를 잰다. ② 베이스라인 A(SQL 필터)·A2(SQL + 계층 매핑)·B(벡터 단독)로 핵심 지표를 먼저 잰다. ③ 제안(그래프 확장 + 규칙 평가기)을 더해 N-07을 잰다. ④ QLoRA·양자화 변형으로 M-03·M-05를 잰다. ⑤ 게이트는 배포마다 전수 점검한다.

**표기 규칙:** 베이스라인 값 없이 목표만 적지 않는다. 확정하면 결정 기록표(§10)에 근거(측정값·표본 수)를 남긴다. 측정하지 못한 칸은 비우지 않고 **"미측정"** 으로 쓴다.

### 0.2 표준 지표 세트와 개선 인정 규칙

문맥 압축, 모델 변형, 검색 전략, 구성 비교 실험은 **아래 9개 지표를 항상 함께 측정**한다. 효율 지표만 보고 "좋아졌다"고 판단하지 않기 위해서다. 문맥 압축에 성공해도 근거가 손실되거나 보안 정책을 위반하면 신뢰성이 개선됐다고 보지 않는다.

| 묶음 | 지표 | ID | 무엇을 막는가 |
|---|---|---|---|
| 품질 | 판정 정확도(자격 판정 일치율) | N-02 (Q-01 병행) | 틀린 판정 |
| 품질 | Faithfulness | Q-05 | 근거 없는 설명 |
| 품질 | Evidence Coverage | Q-11 | 압축·검색 과정에서 근거가 빠짐 |
| 효율 | 입력 토큰 수 | P-08 | 비싸고 느린 컨텍스트 |
| 효율 | Latency | P-01·P-02 | 느린 응답 |
| 효율 | GPU Cost | P-05 | 비용 |
| 보안 | Unauthorized Retrieval Rate | S-09 | 권한 없는 자료가 검색·컨텍스트에 들어감 |
| 보안 | Embedding Reconstruction Risk | S-10 | 임베딩에서 원문이 복원됨 |
| 보안 | Policy Violation Rate | S-11 | 정책 위반 응답 |

**개선 인정 규칙(제안)**

| 순서 | 규칙 |
|---|---|
| 1 | **게이트 먼저.** S-01·S-02·S-04·S-06·S-07·S-09·S-10·S-11, N-03, N-05 중 하나라도 위반하면 그 실험은 "개선"으로 인정하지 않는다. 효율이 아무리 좋아도 채택하지 않는다 |
| 2 | **품질 하한.** N-02·Q-05·Q-11이 기준선 대비 **허용 하락폭 이내**여야 한다(기초 설계서 §9 회귀 게이트 규칙) |
| 3 | **그다음에 효율.** 1·2를 통과한 경우에만 P-08·P-01/P-02·P-05의 개선을 "개선"으로 보고한다 |
| 4 | **압축 예시.** 입력 토큰이 줄었지만 Q-11이 허용 하락폭을 넘으면 "효율 개선, 신뢰성 악화"로 기록하고 채택하지 않는다 |
| 5 | **보고 형식.** 실험 결과표는 9개 지표를 모두 열로 둔다 |

## 1. 수업 예시 KPI의 적용 방안

수업 예시는 이전 주제 작성 시 확인한 값이며 **새 주제 기준으로 재확인하지 않았다.**

| 수업 예시 | 예시 목표 | 우리 프로젝트 적용 | 이유 |
|---|---|---|---|
| Task Success Rate | 90% 이상 | **조정** — 판정과 근거 요건이 모두 맞아야 성공(Q-01) | 성공 조건을 우리 서비스 기준으로 정의해야 함 |
| Accuracy | 90% 이상 | **조정** — 판정 3값(신청 가능 / 신청 불가 / 확인 필요) 일치율(N-02) | 요건 정규화가 소형 모델이라 90%는 근거가 없음 |
| Precision / Recall / F1 | 85% / 85% / 0.85 | **분리 적용** — ① 요건 추출(N-01) ② 후보 검색(E-04·E-05) ③ 계층 확장(N-04)으로 나눔 | 한 숫자로 합치면 의미가 없음. "신청 가능" 오탐(N-03)은 별도 게이트 |
| Latency | 평균 3초 이하 | **바꿈** — 평균이 아니라 **첫 토큰 p95·전체 p95**, 판정 지연(P-01·P-02·P-09) | 스트리밍이고 판정이 설명보다 먼저 나가므로 평균 완료 시간은 맞지 않음 |
| Error Rate | 2% 이하 | **그대로** | 5xx·타임아웃·빈 응답 기준 |
| RAG Faithfulness | 0.90 이상 | **조정** — 설명문에만 적용(Q-05). 시작값은 측정 후 | 한국어 판사 신뢰도·자체 호스팅 소형 판사 문제 |
| System Availability | 99% 이상 | **조정** — 시연·평가 기간 기준(P-04) | RunPod는 필요할 때만 가동(NFR-N08) |
| Cost per Request | $0.01 이하 | **보류** — 산식만 정하고 목표는 GPU·모델 확정 후(P-05) | 모델 크기·GPU가 예산에 따라 결정됨 |
| (없음) | — | **추가** — 요건 추출, 판정 오탐, 계층 확장, 출처 표시, 수집 신선도, SQL 비교, 안전, 모델 비교 | 공고 자격 판정 도메인과 필수 요건에 필요 |

## 2. 답변 품질 (Q)

평가셋: 기초 설계서 §9의 유형(`filter`, `hierarchy`, `definition`, `explanation`, `relation`, `insufficient`, `out_of_scope`, `pii_input`) + 근거 없음(`NO_MATCH`) + 레드팀 케이스, **최소 60문항**(기획 보고서 §5.2 권장, 유형별 최소 수는 팀 결정 `[ ]`). 최적화용(`dev`)과 확인용(`final`, 마지막 1회)을 분리하고 **수집 시점의 공고 스냅샷 버전**을 기록한다. 평가용 프로필은 가상이다. **Q-02는 비워 두었다**(판정 정확도는 N-02로 §3에서 정의).

| ID | 지표 | 정의 / 측정 | 잠정 목표 | 근거·비고 |
|---|---|---|---|---|
| Q-01 | **Task Success Rate** | 정답 질문 중 **판정과 근거 요건 id가 모두 gold와 일치**한 비율. 질문 유형별 | [첫 측정 후 확정] | 판정은 코드, 근거는 그래프에서 나오므로 둘 다 맞아야 성공 |
| Q-03 | **요건 카드·원문 문장 포함률** | 판정을 낸 응답 중 요건 카드와 공고 원문 문장이 1개 이상 포함된 비율(규칙 판정, 모델 호출 없음) | 100% 지향 `[첫 측정 후 확정]` | NFR-N02·FR-N05. 결정적으로 셀 수 있음 |
| Q-04 | **인용 근거 일치율** | 응답이 인용한 요건 id·공고 ID·정의 id가 gold 근거에 포함된 비율. 존재하지 않는 근거 인용은 0건을 목표로 별도 집계 | [첫 측정 후 확정] | 환각 인용은 건수로 본다 |
| Q-05 | **RAGAS Faithfulness** | 설명문이 요건 카드·원문 근거에 충실한 정도(0~1). 설명 생성(`answer`)만 평가. 한국어 `system_prompt` 지정, NaN은 따로 확인 | [첫 측정 후 확정] | 판정 값은 코드가 정하므로 판사가 판정을 바꾸지 않는다(기초 설계서 §9) |
| Q-06 | **RAGAS Answer Relevancy** | 질문과 설명의 관련성 | 기준선 대비 하락 허용폭 이내 | 합격선은 팀이 정함 |
| Q-07 | **범위 밖·근거 없음 거절률** | `OUT_OF_SCOPE`·`LEGAL_ADVICE`·`NO_MATCH`가 정답인 문항에서 해당 고정 응답을 낸 비율 | [첫 측정 후 확정] | 사업계획서 작성·신청 대행·법적 자문 요청에 지어내지 않는 핵심 지표 |
| Q-08 | **과잉 거절률** | 답해야 할 질문을 거절한 비율 | [첫 측정 후 확정] | Q-07만 올리면 모든 질문을 거절하는 시스템이 이김 → 한 쌍으로 본다 |
| Q-09 | **`확인 필요`·`판단 불가` 적절성** | 정보가 부족하거나 요건을 읽지 못한 문항(`insufficient`, `unparsed` 요건 포함)에서 결론 대신 `NEEDS_CHECK`·`판단 불가` 또는 되묻기(최대 2회)를 한 비율 | [첫 측정 후 확정] | FR-N09, MR-N4. 억지 결론을 막는 지표 |
| Q-10 | **값 변경 재판정(what-if) 일치율** | 사용자가 조건 값을 바꿔 다시 판정한 사례에서 재판정 결과·부족 조건 목록이 gold와 일치한 비율 | [첫 측정 후 확정] | FR-N07(P1) |
| Q-11 | **Evidence Coverage** | gold 근거(요건·정의·법령 경로의 간선) 중 **최종 응답이 인용·표시한 비율**. 검색 단계 Recall(E-04)과 달리 생성을 거친 뒤의 값 | [첫 측정 후 확정] | Q-04(정밀도 성격)와 짝으로 본다. 모델 호출 없이 id로 셀 수 있음 |

## 3. 추출·판정·검색 정확도 (N, E)

| ID | 대상 | 정의 / 측정 | 잠정 목표 | 근거·비고 |
|---|---|---|---|---|
| N-01 | **요건 추출 F1** | 팀이 직접 라벨한 표본 공고(추출 결과를 보지 않고 작성, 30건 이상 + 합성 변형 제안)의 조건 JSON과 비교한 P/R/F1. 요건 유형·attribute·operator·값 **완전일치** 기준, 근거 문장 일치는 따로 본다. `unparsed` 비율도 함께 기록 | [첫 측정 후 확정] | `extract` 모델 변형마다 같은 평가셋으로 잰다. 서술형이 많고 소형 모델이라 이전 주제 값을 가져오지 않는다 |

### 4.1 구성 비교 실험 (선택, P2)

시간이 남을 때만 한다. 같은 평가셋·같은 모델·같은 설정으로 3회 반복하고 §0.2의 9개 지표를 함께 보고한다.

| 군 | 구성 | 군별 추가 지표 |
|---|---|---|
| A | 벡터 단독 검색 + 모델 설명(판정을 모델이 함) | N-02, Latency |
| B | SQL 필터 + 규칙 평가기 | N-02, N-03 |
| C | 그래프 확장 + 규칙 평가기 (**제안, 기준 구성**) | N-02, N-03, N-04 |
| D | C + Independent Evaluator(설명문의 근거 지지·정책 위반을 답변 모델과 분리된 평가기가 점검) | **오류 탐지율**(오탐률 병기), 정책 위반율(S-11) |
| E | D + Self-Healing(질의 재작성, 모델 폴백, 규칙 판정 폴백) | **Recovery Rate**, **MTTR**, P-05 |

- Recovery Rate: 모의 장애(모델 서버 중지, 검색 실패, 타임아웃)에서 정상 또는 허용된 degrade 응답에 도달한 비율. MTTR은 P-07과 같은 장애 주입 시험으로 재며 목표는 리허설 측정 후 정한다.
- 평가셋이 작으면 작은 차이는 해석하지 않는다. 일정이 부족하면 D·E를 생략한다.
- 군이 올라갈수록 호출이 늘어 비용이 커진다. 품질 개선이 비용 증가를 정당화하는지 §0.2 규칙으로 판단한다.

## 8. 모델 (LoRA 전후·양자화 비교, 가이드 필수)

세 변형 `base` / `qlora` / `qlora_awq`를 **같은 평가셋**으로 비교한다(기초 설계서 §6.5). 이 주제에서 학습 대상은 **요건 문장 → 조건 JSON 추출** 하나이며 판정은 학습하지 않는다. 판사는 답변 모델과 **분리**하고 설명 품질에만 쓴다.

| ID | 지표 | 잠정 목표 | 근거·비고 |
|---|---|---|---|
| M-01 | **조건 JSON 유효율** | [첫 측정 후 확정] | 출력 형식 강제 + Pydantic 검증. vLLM 구조화 출력은 PoC 확인 전 |
| M-02 | **근거 문장 일치율** | `base` 대비 개선 | LoRA 효과를 보이는 핵심 지표(E-02와 같은 정의) |
| M-03 | **튜닝 효과(N-01·N-02 기준)** | `qlora`가 `base`보다 높을 것 | 수업 결과(이전 문서 승계, 재확인 필요)는 "재현" 능력은 오르지만 "적용" 능력은 거의 안 오를 수 있다는 것이었다. 추출 F1과 하위 판정 영향(N-02·N-03)을 나눠 보고 |
| M-04 | **일반 능력 퇴행** | `base` 대비 하락 허용폭 이내(첫 측정 후) | SFT 후 일반 능력 악화 사례(이전 문서 승계) |
| M-05 | **양자화 손실** | `qlora_awq`가 `qlora` 대비 N-01 하락 허용폭 이내 | 병합은 원래 정밀도 베이스에서 한 뒤 양자화 |
| M-06 | **MLflow 회귀 게이트** | 절대 하한 + 허용 하락폭 + 사례별 회귀 + 평가 완전성, 4규칙 통과 | 기준선은 `baselines/baseline.json`, pytest·GitHub Actions 판정 |

| M-08 | **폴백 provider 품질** | 폴백 후보(`base`·대체 호스트 등)의 N-01·N-02 하락폭을 같은 평가셋으로 측정 | 허용 하락폭은 측정 후. **측정하지 않은 provider는 활성화하지 않는다**(기초 설계서 §3). 외부 API 폴백은 기본 비활성이며 사용자 조건은 보내지 않는다 |

## 10. 목표 확정 절차

1. **확인 먼저**: 수집 API 시험 호출(D-06)과 무작위 표본 요건 분석(D-04)으로 데이터 확보 가능성과 요건 구조를 확인한다. 이 결과가 약하면 주제 전환 결정을 다시 본다(기획 보고서 부록 D #1).
2. **베이스라인 측정**: 베이스라인 A·A2·B와 `base` 모델로 §2~§4 지표를 먼저 잰다(같은 설정 3회 반복해 흔들림도 기록).
3. **잠정 목표 조정**(§0.1의 게이트는 조정하지 않는다): 달성이 비현실적인 목표는 근거(측정값·표본 크기)와 함께 수정하고 결정 기록표에 남긴다. **결과를 보고 합격선을 임의로 내리지 않도록 조정 시점은 중간 발표 전 1회로 정한다.**
4. **확정본**을 기획 보고서 §8.2 표에 반영한다.
5. 최종 발표 전 **확인용 평가셋(`final`) 1회**로 확정 목표 대비 결과를 보고한다.

## 11. 한계와 미확인

- **모든 목표값은 측정 전 추정이다.** 특히 N-01·N-02·G-02는 소형 모델 품질에 크게 좌우되며 모델 크기·GPU가 미정이다.
- **표본이 작고 치우쳐 있다.** 사전 확인은 한 포털의 하루치 15건이며, 요건 라벨 표본과 평가셋은 아직 만들지 않았다.
- **평가용 프로필은 가상이다.** 가상 프로필의 난이도가 실제 사용자 조건을 대표하지 않을 수 있다. 공고가 바뀌면 정답이 낡으므로 스냅샷 버전을 기록한다.
- **법령·제도 정의**(중소기업 규모 기준 등)는 원문 확인 전이다. G-02·O-02는 법령 원문을 확보한 범위에서만 잰다.
- **API 실응답을 보지 못했다.** E-03·N-06의 기준과 K-Startup 개발계정 트래픽 "10,000"의 단위는 미확인이다.
- RAGAS는 영어 지시문 기반이라 한국어에서 점수가 흔들릴 수 있고, 수업의 판사는 외부 API였다. **자체 호스팅 소형 판사의 신뢰도**는 M-07로 직접 확인해야 한다.
- 에이전트 지표(G-05)와 계층 확장 Recall(N-04)의 정의는 우리가 정한 것이다.
- Aura·RunPod·Vercel의 한도와 가용성은 확인하지 않았다(P-04).
- 이 문서는 신청 자격이나 선정 결과의 정확도를 보증하지 않는다. 서비스는 **참고용 검토 보조**이며 최종 확인은 공고 원문과 주관기관이 한다.
