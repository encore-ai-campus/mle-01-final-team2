# 첨부 공고문 추출 가이드 (동료용, v0.1 초안)

> 대상 독자: 첨부 파일(공고문·신청서·안내문)에서 요건 정보를 뽑는 작업을 맡는 사람
> 목적: **무엇을** 뽑고 **어떤 방식으로** 뽑으며 **무엇을 하지 말아야 하는지**를 정한다.
> 상태: 초안. 수치는 우리가 기업마당 1,294건에서 직접 돌려 본 결과이고, K-Startup 첨부는 아직 확인하지 못했다(§1).
> 근거 문서: [MLE_2팀_기초 설계.md](../plan/MLE_2팀_기초%20설계.md) §4~5, [GOLDSET_라벨링_가이드_v0.1.md](../GOLDSET_라벨링_가이드_v0.1.md), [REVIEW_적재데이터_v3_점검결과.md](../old/REVIEW_적재데이터_v3_점검결과.md)

## 0. 한눈에 보기

| 질문 | 답 |
|---|---|
| 왜 첨부가 필요한가 | API 본문은 요약뿐이다. 기업마당 API 요약은 평균 285자인데 공고문 첨부 추출 텍스트는 평균 6,205자(중앙값 약 3,920자)이고, 제외 요건·세부 자격·평가 기준·법령 인용이 첨부에 있다. K-Startup API 본문은 중앙값 115자다. |
| 이 단계가 하는 일 | **텍스트와 근거 후보를 정확히 뽑아 저장**하는 것까지. |
| 이 단계가 하지 않는 일 | 요건을 `Condition`(속성·연산자·값)으로 **정규화하거나 신청 가능 여부를 판정하지 않는다.** 그것은 다음 단계다. |
| 가장 중요한 규칙 | **원문에 있는 문장만 뽑고, 모든 항목에 원문 그대로의 근거(`evidence_text`)와 위치를 붙인다.** 없는 내용은 만들지 않는다. |
| 정답셋과의 관계 | 이 추출 결과는 **정답이 아니라 평가 대상**이다. 정답은 사람이 원본을 읽고 따로 만든다. 추출 결과를 보고 정답을 쓰면 평가가 오염된다. |

## 1. 대상 파일

### 1.1 소스별 상황

| 소스 | 첨부 확보 방법 | 현황 |
|---|---|---|
| 기업마당 | API 응답의 첨부 URL(실행 때마다 새로 발급되는 `downloadToken` 필요). 우리 도구로 자동 수집 | 본문 출력 파일(공고문) 1,294개를 받아 추출을 마쳤다. 일반 첨부 1,360개는 아직 받지 않았다. |
| K-Startup | API는 첨부 정보를 주지 않는다. 공고 페이지·첨부 경로는 `robots.txt`가 막고 있어 **자동 수집을 하지 않는다.** | 사람이 브라우저로 직접 확인한 파일만 쓴다. 필요성은 비교 시트(`data/goldset/kstartup_api_vs_page_check_v0.1.csv`) 결과를 보고 정한다. **그 전에는 K-Startup 첨부 추출을 시작하지 않는다.** |

### 1.2 우선순위

| 순위 | 파일 | 뽑는 이유 |
|---|---|---|
| 1 | **공고문 본문**(기업마당 `PRINT_BODY`, 파일명에 "공고문") | 자격·제외·평가·서류가 모두 있다 |
| 2 | 신청서·양식·확약서·동의서 | 제출 서류 목록과 신청 항목을 알 수 있다. 요건이 아니다. |
| 3 | 안내 책자·매뉴얼 | 대부분 사용법이다. 자격 요건이 있는 경우에만 |
| 4 | `.zip` | 먼저 **안에 공고문이 있는지** 파일 목록만 본다(예: `120414`의 zip은 붙임 6개 — 신청서·동의서·매뉴얼·분류코드 — 였고 공고문은 없었다) |

### 1.3 다루지 못하는 파일 (상태만 기록하고 건너뛴다)

| 파일 | 처리 |
|---|---|
| 배포용 hwp(복사 제한 문서) | `DISTRIBUTION_DOC_UNSUPPORTED`로 기록. **복호화하지 않는다**(작성자가 복사를 제한한 문서). 기업마당 2건 |
| 이미지(png·jpg), 스캔 PDF | OCR(Tesseract)로 읽되 **낮은 신뢰**로 표시한다(`OCR_LOW_TRUST`). 확정 근거로 쓰지 않는다. 기업마당 126건(9.7%) |
| 서버가 거부하는 파일(HTTP 403) | 우회하지 않고 기록만 한다 |

파일 형식은 **확장자가 아니라 파일 앞부분(매직 바이트)으로 판별**한다. 확장자와 실제 형식이 다른 경우가 있다.

## 2. 무엇을 뽑는가

### 2.1 추출 대상 항목

판정에 쓰는 것은 ① 자격과 ② 제외 두 가지이므로 **이 둘을 가장 정확히** 뽑는다. 나머지는 있는지와 위치를 기록한다.

| # | 항목(`label`) | 설명 | 비고 |
|---|---|---|---|
| 1 | `ELIGIBILITY` | 신청 자격·지원 대상·모집 대상 | 지역(거주·사업장·주소), 업력, 연령, 기업 규모, 업종, 인증·등록(확인서), 수혜 이력 등이 한 문장에 섞여 있어도 **문장을 나누지 말고 통째로** 뽑는다. 정규화는 다음 단계 |
| 2 | `EXCLUSION` | 신청 제외·결격·참여 제한·지원 불가 | 항목이 번호로 나열되면 **항목마다 하나씩** |
| 3 | `PREFERENCE` | 우대·가점 | 판정에 쓰지 않는다. 별도 표시 |
| 4 | `BENEFIT` | 지원 내용·규모·한도·횟수·금액 | 한도·횟수는 `LIMIT`로 쓰일 수 있다 |
| 5 | `PERIOD`, `METHOD` | 신청 기간, 신청 방법 | 상시·예산 소진 같은 날짜 아닌 표기는 **원문 그대로** |
| 6 | `DOCUMENT` | 제출 서류 목록 | 서류명은 항목별로 |
| 7 | `CRITERION` | 평가·선정 기준, 배점표, 최소 점수 | 표는 행 단위로 |
| 8 | `OBLIGATION` | 선정 후 의무(입주 후 사무실 이전, 사후 보고 등) | 신청 자격이 아니다. 자격과 섞지 않는다 |
| 9 | `TRACK` | 대상별로 조건·지원이 다른 구분(유형Ⅰ·Ⅱ, 농업인·농업법인 등) | 어느 요건이 어느 트랙에 걸리는지 표시 |
| 10 | `LAW_REF` | 「법령명」·조·항 인용과 용어("중소기업", "소상공인", "창업기업") | 뜻을 쓰지 않고 **인용 문구와 위치만** |
| 11 | `TABLE` | 별표·붙임의 업종·지역·제외 업종 목록 | 표를 평문으로 잇지 말고 **행 단위로 보존** |
| 12 | `CHANGE_NOTE` | "정정", "연장", "변경 사항" 안내 | 재공고·정정 연결(`SUPERSEDES`)의 단서 |
| 13 | `CONTACT` | 문의처 | 공공기관 연락처는 **그대로 둔다**(마스킹 불필요) |

### 2.2 모든 항목에 붙이는 공통 속성

| 속성 | 값·규칙 |
|---|---|
| `evidence_text` | **원문 그대로** 복사한 문장(수정·요약 금지). 길면 핵심 문장 하나와 `evidence_extra` 배열 |
| `source_file`, `source_type` | 파일명, `PDF`/`HWP`/`HWPX`/`OCR`/`API`. **API 값과 파일 값을 섞지 않는다**(§4) |
| `page` | PDF·OCR(PDF)일 때만 쪽 번호. 그 외는 `null`. **API 값에는 쪽 번호를 붙이지 않는다** |
| `char_start`, `char_end` | 추출 텍스트 안의 위치 |
| `extraction_method` | `rule`(정규식·제목 탐지) / `model`(LLM 등, 모델명 기록) |
| `fact_status` | `observed_in_text`(원문에서 직접 확인) / `needs_human_review`(자동 추출 후보) / `ambiguous`(원문이 불명확) |
| `track_id` | 트랙에 걸린 항목이면 |
| `note` | 라벨러·추출기가 확신하지 못한 곳. 비우지 않는다 |

## 3. 어떻게 뽑는가

### Step 1. 파일 분류
매직 바이트로 형식을 판별하고(`pdf`, `hwp`, `hwpx`, `zip`, `png`, `jpg`), 위 §1.3에 해당하면 상태만 기록한다.

### Step 2. 텍스트 추출
우리가 만든 도구를 재사용할 수 있다(저장소에 올린 뒤 공유한다).

```powershell
python tools/extract_attachment_text.py --files data/bizinfo/files/<run> --ocr --workers 8
```

| 형식 | 방법 | 알아 둘 한계 |
|---|---|---|
| PDF | PyMuPDF, 쪽마다 `=== p.N ===` 구분선 | 쪽당 글자가 30자 미만이면 스캔본(`NEEDS_OCR`). 일부 PDF는 띄어쓰기가 빠진다 |
| hwp(5.x) | OLE 본문 스트림을 압축 해제해 `PARA_TEXT` 레코드를 읽는다 | 표 안 글자가 문단으로 한 줄씩 나와 **표 구조가 없다**. 배포용·암호 문서 불가 |
| hwpx | zip 안 `Contents/section*.xml`의 문단·표 셀 | 표 구조 손실(셀 문장이 한 줄씩) |
| 이미지·스캔 PDF | Tesseract `kor+eng`. 읽기용 `*.txt`와 공백을 줄인 검색용 `*.search.txt`를 같이 만든다 | 한국어는 음절 사이에 공백이 끼고(`모 집 공 고`) 장식 글자가 잡음으로 섞인다 |

기업마당 1,294건 결과: 일반 추출 1,166건, OCR 126건, 읽지 못함 2건(배포용 hwp). 텍스트 길이는 평균 6,205자, 중앙값 약 3,920자.

### Step 3. 정제 (노이즈 제거)
지난 점검에서 방송광고 공고의 `eligibility` 구간이 **"개정 2019. 1. 1 시행…" 같은 개정 이력과 서로 다른 조항이 뒤섞인 글**이었다. 다음은 요건 후보로 만들지 않는다.

- 개정·시행 이력 줄, 머리글·바닥글·쪽번호, 목차, 서식 안내 문구
- 같은 문장의 반복(문서 앞의 요약과 뒤의 본문이 같은 경우는 **둘 다 두되** 같은 `group`으로 표시)

### Step 4. 구간 나누기
제목 줄을 찾아 구간 **후보**를 만든다. 우리 도구가 제목 줄(`신청자격`, `지원대상`, `제외 대상`, `제출서류`, `평가 기준` 등)을 찾아 위치를 기록한다.

- 기업마당 결과: 신청자격 후보가 있는 파일 1,102개, 제외 후보가 있는 파일 623개. **오탐이 있다**("지원자격 적절성 등을 검토하여…" 같은 문장 줄이 제목으로 잡힘).
- 한 파일에 같은 제목이 여러 번 나온다(전체에서 한 파일의 신청자격 제목이 최대 134번이었다. 표·반복되는 서식 때문으로 보이며 원인은 확인하지 않았다). **구간을 합치지 말고 모두 보존**한다.
- 구간 후보는 확정이 아니다. 추출 결과의 `fact_status`는 `needs_human_review`다.

### Step 5. 요건 후보 추출
**규칙 우선, 모델은 보조**로 쓴다.

1. 구간 안에서 문장을 나눈다(번호 `1)`, `가.`, `○`, `-`, `※` 단위).
2. 패턴으로 `ELIGIBILITY`·`EXCLUSION`·`DOCUMENT` 등을 태깅한다(`이내`·`미만`·`만 ○세`·`소재`·`관내`·`제외`·`결격` 등).
3. 모델(LLM)을 쓴다면 프롬프트 규칙: (a) 입력 텍스트 안의 **문장을 선택**하고 새 문장을 만들지 않는다, (b) `evidence_text`가 없으면 `null`, (c) 해석·보완 금지, (d) 모델명·프롬프트 버전을 기록한다.
4. 트랙(유형·대상별)이 있으면 `TRACK` 항목을 만들고 요건에 `track_id`를 붙인다.
5. 법령 인용은 정규식 「…」와 `제○조` 패턴으로 위치만 기록한다.

### Step 6. 자동 검증 (저장 전에 항상 통과)
| 검사 | 기준 |
|---|---|
| `evidence_text`가 추출 텍스트에 **그대로** 있는가 | 100%(공백 정규화 후 부분 문자열 검사). 없으면 저장하지 않는다 |
| `page`가 해당 텍스트의 쪽과 맞는가 | PDF·OCR(PDF)에 한해 100% |
| `source_type`이 올바른가 | API 값에 `page`가 붙어 있지 않다 |
| 빈 `evidence_text`, 개정 이력 문구 | 0건 |
| OCR 항목 | `source_type=OCR`, `fact_status=needs_human_review`로만 저장 |

### Step 7. 사람 검토 표본
파일 20개 정도를 뽑아 사람이 원본과 비교한다. 누락(원문에 있는데 못 뽑음)과 오탐(요건이 아닌데 뽑음)을 센다. 지표 정의와 합격선은 **결과를 보기 전에** 팀이 정한다 `[ ]`.

## 4. 저장 형식

**별도 파일에 저장하고, API 필드나 청크 본문에 섞지 않는다.** 지난 점검(v3)에서 PDF 추출 텍스트가 청크 본문에 들어가 기업마당 청크가 중앙값 470자에서 1,267자로 늘고 "자동 추출 후보(검토 필요)" 문구까지 임베딩된 문제가 있었다. 검토를 마친 값만 나중에 청크·그래프에 올린다.

`data/<소스>/attachment_extractions/<run>/attachment_extractions.jsonl` (파일 하나당 한 줄, **JSON 객체로 저장**. 문자열로 직렬화하지 않는다)

```json
{
  "notice_id": "BIZINFO:PBLN_000000000127987",
  "source_file": "127987_1_2027년청년어촌정착지원사업희망자모집공고+.pdf",
  "format": "pdf", "status": "OK", "pages": 23, "chars": 16789,
  "text_extraction": {"tool": "extract_attachment_text.py", "ocr": false, "warnings": []},
  "items": [
    {
      "label": "ELIGIBILITY", "group": "G1", "track_id": null,
      "evidence_text": "연령 : 사업 시행연도 기준 만 18세 이상 ~ 만 40세 미만 (1987. 1. 1. ~ 2009. 12. 31. 출생자)",
      "source_type": "PDF", "page": null, "char_start": 0, "char_end": 0,
      "extraction_method": "rule", "fact_status": "needs_human_review", "note": ""
    }
  ]
}
```

위 예시는 **형식 설명용**이다. 위치 값(`page`, `char_*`)은 실제 추출 때 채운다. 인용한 문장은 우리가 읽은 부안군 청년어촌정착 공고의 신청 자격 항목 일부다.

**필드 이름·값 규칙**
- `label`은 §2.1의 영문 값만 쓴다.
- 날짜·금액·인원은 **원문 문자열 그대로** 두고 정규화하지 않는다(정규화는 다음 단계).
- `region`·`business_age` 같은 판정 속성 이름은 이 단계에서 만들지 않는다.

## 5. 하지 말 것

| # | 금지 | 이유 |
|---|---|---|
| 1 | 원문에 없는 내용을 추론·보완해 쓰기 | 거짓 확신이 `신청 가능` 오판이 된다 |
| 2 | 법령·제도 용어("중소기업", "여성기업")의 뜻을 기억으로 쓰기 | 법령 내용은 원문 확인 전이다. 용어와 인용 문구만 기록 |
| 3 | 개정 이력·서식 문구를 요건으로 분류하기 | 지난 점검에서 나온 오분류 |
| 4 | OCR 결과를 확정 근거로 쓰기 | 낮은 신뢰, 글자 오인식이 있다 |
| 5 | 정답셋 후보 공고의 추출 결과를 라벨러에게 보여 주기 | 정답이 오염된다. 정답은 원본을 읽고 쓴다 |
| 6 | 배포용 hwp 복호화 | 작성자가 복사를 제한한 문서 |
| 7 | 403 등 서버가 거부한 파일을 우회해 받기 | 접근 거부를 존중한다 |
| 8 | K-Startup 공고 페이지·첨부의 자동 수집 | `robots.txt`가 막고 있다 |
| 9 | 첨부 원본·추출 텍스트를 저장소에 올리기 | 용량과 저작권. 로컬에만 둔다(`.gitignore` 적용) |
| 10 | API 값과 첨부 값을 같은 필드에 섞기 | 근거 출처가 구분되지 않는다 |

공공기관 담당자의 이메일·전화번호 같은 문의처는 **마스킹하지 않는다.**

## 8. 한계

- hwp·hwpx 추출은 표 안 글자의 행·열 구조를 보존하지 않는다. 별표·배점표는 행 단위로 읽기 어렵다.
- 제목 탐지는 규칙 기반이라 형식이 다른 공고에서 놓치거나 오탐한다. 정확도는 측정하지 않았다.
- OCR은 설치된 작은 한국어 모델(`kor` 1.6MB)이라 정확도가 낮을 수 있다.
- K-Startup 첨부는 확보 방법과 필요성이 모두 미정이다. 위 수치는 모두 기업마당 기준이다.
- 본 가이드의 항목·필드는 사례 몇 건에서 정한 것이라 파일 20건 표본 후 고친다(v0.2).
