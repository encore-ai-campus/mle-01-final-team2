# 값 정규화 층과 첨부 읽기 (v0.1)

> 지원각(정부지원사업 신청 자격 판정 서비스) / 근거 it(2팀)
> 기준: 정리층 `data/cleaned/20261124/`(공고 5,116건), 정규화 층 `data/normalized/20261124/`(git 제외, 로컬 전용)
> 도구: `tools/normalize_values.py`, 시험 `tools/test_normalize_values.py`(7건), 전체 시험 84건 통과

## 1. 먼저 바로잡을 것

앞서 "OCR이 필요한 첨부 약 126건을 읽지 못했다"고 보고했으나 **틀렸다.** 126건은 이미 Tesseract(kor+eng)로 읽혀 `OK_OCR` 상태이고 정리층 청크에 들어 있다(`ATTACHMENT_OCR` 231청크). 실제로 읽지 못한 첨부는 **배포용 hwp 2건**뿐이었다.

## 2. 첨부 읽기

| 구분 | 건수 | 처리 | 신뢰 |
|---|---|---|---|
| 일반 추출(pdf·hwp·hwpx) | 1,166 | 본문 직접 추출 | 높음 |
| OCR(이미지·스캔 PDF) | 126 | Tesseract. 중앙값 신뢰도 84.9, 75 미만 13건 | 낮음 표시 유지 |
| 배포용 hwp | 2 | 한글에서 PDF로 다시 저장한 파일을 받아 OCR(2026-11-25 보충). 120138 신뢰도 91.4(6쪽), 120414 신뢰도 86.4(7쪽) | 낮음(OCR) |

- 배포용 hwp 2건: `BIZINFO:PBLN_000000000120138`(인천 중동 수출기업 긴급 경영안정자금), `BIZINFO:PBLN_000000000120414`(세종 기술닥터제). 본문 암호는 풀지 않았고 **사람이 한글에서 PDF로 저장한 파일**을 `data/bizinfo/files/manual_20261125/`에 넣어 읽었다. 한글 PDF는 글자가 아닌 이미지라 OCR이 필요했다.
- 120138의 별첨(지원대상 업종 안내)과 신청 매뉴얼 PDF 2개도 함께 반영했다(글자 PDF, 매뉴얼은 34쪽).
- 보충 추출 결과는 `data/bizinfo/extracted/00_manual_20261125/`에 있고, 정리층 생성 때 자동으로 합쳐진다(폴더 이름 `00_manual_`로 시작하면 보충분으로 본다). 정리층은 공고 5,116건, 청크 32,947개이며 ID 중복은 없다. 보충된 공고 본문이 PDF로 들어왔으므로 앞서 넣었던 미리보기 청크는 빠졌다.
- 120414의 `첨부파일.zip`(신청 서식 hwp)은 요건 근거가 아니라 반영하지 않았다(`_unused/`에 보관).
- OCR 첨부가 있는 126개 공고는 모두 **OCR 외에 읽힌 첨부가 없다.** 즉 이 공고들의 첨부 근거는 전부 낮은 신뢰다(보충한 두 공고문도 OCR이라 같다).
- 사람이 원본 이미지와 대조할 목록: `data/normalized/20261124/ocr_review.csv`(신뢰도 75 미만 또는 200자 미만 16건). 가장 낮은 것은 `126098`(48.8).

## 3. 값 정규화 층이 하는 일

정리층을 건드리지 않고 그 위에 공고별 **정규화 값 후보**를 쌓는다. 전부 검수 전(`unreviewed`)이며 모든 값에 원문 문장을 수정 없이 붙였고, 생성 직후 원문 일치를 검사했다(불일치 0).

| 종류 | 만드는 값 | 출처 |
|---|---|---|
| 구조화 필드(K-Startup) | 업력 옵션 → 상한·예비창업자 허용·필터 정보성, 대표자 연령 옵션 → 허용 구간, 신청 대상 옵션 → 개념 ID | API 선택형 필드 |
| 본문·첨부 규칙 | 업력, 대표자 연령, 지역(소재·관내·거주 등), 법령 인용, 제외 문구, 인증, 기업 규모 | 정규식(`TEXT_RULE`), OCR(`OCR_TEXT`), 미리보기(`PREVIEW_TEXT`) |
| 용어 일치 | 신청자 유형 사전 24종 표기 일치(정의는 만들지 않음) | `data/ref/term_standard_v0.1.json` |
| 지역 | 정리층의 지역 개념 ID 그대로(적용 범위 확정 아님) | 소관기관·지원 지역 필드 |

### 결과

|---|---|---|

| 규칙 값 수(업력·연령·지역·법령 등) | 합계 17,253(두 출처 합). 2026-11-25 정리 후 지역 조건 +42(코드표 누락 시군구), 제외 후보 연산자 `TEXT_ONLY`(3,347), 사회적기업·여성기업·장애인기업 232건은 `certification`으로 이동 | 이전 17,211 |

| OCR 출처 값 / 미리보기 출처 값 | 67 / 0 (전체) | |
| 지역 값 중 모호 표기(동명 시군구 등) | 43 (전체, 개념 확정 안 함) | |

### K-Startup 선택형 필드는 조건이 아닐 수 있다

K-Startup의 업력·연령·신청 대상 필드는 검색 필터의 체크박스라, **전부 고른 공고는 제한이 없다는 뜻이 아니라 필터가 정보를 주지 않는다는 뜻**이다. 이런 값은 `all_options`로 표시하고 판정에 쓰지 않는다.

| 필드 | 전부 고른 공고 | 비율 |
|---|---|---|
| 업력 | 1,354 | 35% |
| 대표자 연령 | 2,602 | 68% |
| 신청 대상 | 1,380 | 36% |

신청 대상의 "일반기업"은 중소기업과 같다고 보지 않고 **미정**으로 둔다(단위 시험에 포함).

### 구조화 업력과 본문의 충돌

업력 필터에 정보가 있는 K-Startup 1,269건 중 본문의 업력 상한과 필터의 상한이 **일치 1,169, 본문이 더 좁음 78, 본문이 더 넓음 22**다. 어긋난 100건은 `conflicts_business_age.csv`에 있고 정답셋의 `source_conflicts` 후보다. 어느 쪽이 맞는지는 사람이 원문으로 정한다. 지금은 **본문을 우선**하는 것이 가이드의 기본이다.

## 4. 이 단계에서 하지 않은 것

- 법령 정의의 적용(예: "창업기업=7년 이내"를 업력 조건으로 자동 변환)은 하지 않았다. 용어 일치까지만 한다.
- 업종 정규화는 하지 않았다. 업종 사전이 없다.
- 두 공고 이상을 합친 판단(연장·재공고 묶음 111건 등)은 사람 검토 전이다.
- 정규화 층은 정답이 아니다. 정답은 사람이 쓴 라벨이며(파일럿 10건), 이 결과는 라벨러에게 보여 주지 않는다.

## 5. 동료 산출물과의 관계

K-Startup 전처리는 정리층 + 정규화 층이 **대체**한다. 동료가 만든 `data/kstartup/processed/kstartup_cleaned.jsonl`·`kstartup_conditions.jsonl`·`kstartup_chunks.jsonl`(어제 16시)은 더 이상 수정을 요청하지 않아도 된다. 이후 파이프라인(그래프·검색·정답셋)은 정리층과 정규화 층을 입력으로 쓴다. 이전 산출물은 비교용으로 남겨 둔다.

## 6. 다시 만드는 법

```powershell
python tools/preprocess_notices.py
```

```powershell
python tools/normalize_values.py
```

정리층을 다시 만든 뒤 정규화 층을 다시 만든다. 둘 다 같은 입력이면 같은 결과가 나온다.
