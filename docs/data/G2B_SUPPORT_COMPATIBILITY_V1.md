# 나라장터·지원사업 공통 정규화 호환성 검토
작성일: 2026-11-25

## 범위와 처리 원칙

기존 `data/normalized/v1/20261124` 지원사업 스냅샷과 저장소에 이미 있는 `data/g2b_monthly` 월별 JSONL/CSV만 사용한다. 입력 파일은 덮어쓰지 않는다. API 재호출, 파일 다운로드·본문 추출, DB 적재, 조건 추출과 판정은 수행하지 않는다. 통합 산출물은 기존 스냅샷과 별도인 `data/normalized/v1/20261125_g2b`에 생성한다.

지원사업 공고와 입찰 공고는 `notice_type`으로 구분한다. 공통 필드에는 동일 의미의 값만 매핑하고, 입찰 전용 분류·면허·지역·제한 플래그·계약/낙찰 방식·예정가격·문서 메타데이터는 `source_metadata.source_specific.G2B` 아래 보존한다. JSONL 원본의 부속 목록을 기준으로 삼고, 불일치하는 CSV를 이용해 값을 합성하거나 보정하지 않는다.

## G2B 입력 현황

| 항목 | 관찰 결과 |
|---|---:|

| 공고일 범위 | 2025-11-24–2026-11-22 |

통합 출력 재검사에서 G2B 상세 URL 192,064건과 문서 URL 532,414건 모두 `VALID`였다.

조건 후보 필드 규모는 면허 125,541 공고/262,928 항목, 지역 77,345 공고/109,156 항목, 업종 제한 `Y` 125,536건, 참가 제한 `Y` 1,019건이다. 플래그는 의미가 확인된 판정 조건이 아니라 원천 후보의 건수다.

데이터 명세의 1년 용역 취소 제외 공고 수 179,382건과 JSONL 전체 중 취소 표시를 제외한 179,417건 사이에 35건 차이가 있다. 집계 모집단(명세는 용역, JSONL은 물품·공사 표본도 포함)이 다를 가능성이 있어 단순 오류로 확정하지 않고 대조 검수 이슈로 기록한다. `licenses.csv`는 262,888행으로 JSONL 내포 목록보다 40항목 적다. 공고 CSV와 지역 CSV는 JSONL 관찰 수와 일치한다. 불일치는 원본 보정 없이 유지한다.

## 공통 스키마 매핑과 의미 제한

- `notice_id`는 `G2B:<공고번호>:<차수>`로 네임스페이스를 분리하고, 원본 ID는 `source.source_id`에 둔다.
- `notice_type=PROCUREMENT_BID`; 기존 BIZINFO/K-Startup 출력에는 통합본에서 `SUPPORT_PROGRAM`을 부여한다.
- 공고명, 공고기관/수요기관, 원 공고일, 마감일, 출처 분류는 의미가 같은 공통 필드에 매핑한다. 입찰 마감일은 지원사업 신청 시작/종료일로 복제하지 않는다.
- 면허, 참가 제한 플래그, 지역 목록은 조달 원문 필드 그대로 별도 네임스페이스에 보존한다. 이 값만으로 신청 자격·배제 조건을 확정하지 않는다.
- 첨부는 파일명/URL/건수 메타데이터만 보존한다. 텍스트 추출 상태는 알 수 없음이며 다운로드와 텍스트 추출을 실행하지 않는다.
- 기관/담당자 이름은 연락처로 복사하지 않는다. 업무 맥락이 명시되지 않은 전화·이메일 값은 서비스 출력에서 숨기고 검수 대상으로 남긴다.

## 조건 데이터 호환성

공유 월별 데이터에는 자연어 입찰 자격 본문, 배제·제재 조항 전문, 우대·가점 평가 문구, 공동수급·실적 조항 전문이 없다. 면허/지역/참가 제한 필드는 후속 원문 검토 후보일 뿐 조건 판정 근거로 승격하지 않는다. 조건 스키마의 `UNCLASSIFIED`, `UNKNOWN`, `UNREVIEWED`, `NOT_COLLECTED`, 빈 논리 루트 구조를 재사용하므로 조건 전용 스키마 확장은 필요하지 않다.

`sample_data/conditions/actual-condition-samples.jsonl`에는 면허, 지역, 업종 제한 표시, 참가 제한 표시를 각각 나타내는 G2B 실제 필드 표본을 포함한다. 이 표본들은 조건 유형 미분류, 연산자/값 미설정, 검수 미완료, 검색 및 판정 비대상으로 유지한다. 기업마당/K-Startup 기존 7개 표본은 기존 정규화 스냅샷과 청크 근거 연결을 그대로 사용한다.

통합 변환 보고서 `data/normalized/v1/20261125_g2b/normalization_report.json` 및 이슈 파일 `normalization_issues.jsonl`의 실측 결과:

- 통합 공고 197,180건 (BIZINFO 1,294, K-Startup 3,822, G2B 192,064), 청크 32,947건 (G2B 0)
- 스키마 오류 0, 개인정보 잔존 0, 공고 ID 중복 0, 청크 ID 중복 0, 고아 청크 0, 변환 이슈 0
- 상세 URL 192,064건 및 문서 URL 532,414건 모두 HTTPS 공식 도메인 검사 통과
- 담당자명 필드 192,027건 및 수행자명 필드 192,028건 생략; 업무 맥락 미확인 전화 후보 187,404건 모두 값 비노출 검수 대상으로 분류
- 출력 JSONL은 약 1.36GB; 입력 해시와 변환 결과 통계는 보고서에 보존
- 단위/회귀 테스트 29개 통과 (`tests.test_normalize_support_data`, `tests.test_public_notice_pipeline`, `tests.test_g2b_normalization`, `tests.test_condition_schema`)
- 기존 2026-11-24 정규화 입력은 읽기만 했으며, 보고서의 입력 SHA-256과 사후 해시가 일치함. 첨부 다운로드/본문 추출/조건 추출/DB 변경은 모두 미수행
- 다운로드/텍스트 추출/DB 변경: 수행하지 않음
- 조건 논리 스키마 확장: 없음. 정규화 공고 스키마에 선택적 `notice_type` 및 네임스페이스된 G2B source-specific 구조만 추가

## 미해결 이슈 및 다음 단계

### BLOCKER

- 현재 공유 입력만으로 실제 입찰 자격·제외·우대·예외 문구의 의미를 조건 구조화할 수 없다. G2B 원문/첨부 텍스트가 제공되기 전까지 입찰 참가자격 판정 및 조건 표본 검증은 보류해야 한다. 정규화 호환성 작업 자체는 완료되었으며, 이 제한은 조건 추출·판정 단계의 범위 제한이다.

### NON_BLOCKER

- 명세의 취소 제외 공고 수와 전체 JSONL의 취소 제외 수가 35건 다르다. 명세는 용역 대상, JSONL은 물품·공사 표본을 포함하므로 집계 범위 대조가 필요하다.
- 내포 면허 목록과 평탄화 `licenses.csv` 사이에 40항목 차이가 있다. 공통 통합본은 JSONL 내포 값만 보존했다.
- G2B 원천 필드 의미 일부가 현재 공유된 공식 API 문서로 확인되지 않는다. 해당 의미를 확정하지 않고 source-specific 값으로 보존했다.

### EXPECTED_DIFFERENCE

- G2B 공유 월별 투영본은 상세 본문 청크를 제공하지 않는다. 그래서 G2B 청크 0건이며 지원사업 청크 32,947건만 통합 스냅샷에 포함했다.
- 나라장터는 입찰 공고이므로 지원사업의 신청 기간·신청 URL·자격 텍스트와 필드 제공 범위 및 용어가 다르다. 값이 없으면 채우지 않고 원천 전용 영역과 `NOT_COLLECTED` 상태를 사용한다.
