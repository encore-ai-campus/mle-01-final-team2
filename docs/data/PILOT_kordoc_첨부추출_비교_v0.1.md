# kordoc 첨부 추출 비교 시범 v0.1

- 작성일: 2026-11-27
- 목적: 한국어 문서 파서 [kordoc](https://github.com/chrisryugj/kordoc)(MIT)이 지금 쓰는 첨부 추출기 `tools/extract_attachment_text.py`보다 나은지 표본으로 확인하고 채택 여부를 정한다.
- 결론 요약: **HWP·HWPX의 표 구조, 배포용 HWP, OCR에서는 kordoc이 확실히 낫다. 글자 PDF는 비슷하다.** OCR은 한 글자 토큰 비율이 0.72에서 0.10으로 떨어졌고, 자격 구간(ELIGIBILITY)이 잡힌 문서가 10건 중 1건에서 7건으로 늘었다(§3). 기존 추출을 덮어쓰지 않고 "새 추출 스냅숏"으로 병행 도입하는 것을 권한다(§5).

## 2. 결과

읽는 법:

- **글자 양은 거의 같다**(차이 1% 안). 빠뜨리는 글은 없다고 봐도 된다.
- **표는 kordoc만 구조를 남긴다.** 기존 추출은 표 칸을 한 줄씩 풀어 써서 행·열 관계가 사라진다. 원본 표 컨트롤 수(668·270)에는 중첩 표와 배치용 표가 들어 있어서 260·217을 "놓친 표"로 읽으면 안 된다.
- **한 글자 토큰 비율이 조금 낮아졌다**(0.17→0.16). 줄바꿈으로 단어가 끊기는 일이 kordoc 쪽이 조금 적다는 뜻이다.
- **자격·제외 구간 탐지 수는 같다.** 현재 `find_sections` 규칙 기준으로는 손해도 이득도 없다.
- **배포용 HWP 2건은 kordoc만 읽었다.** 기존에는 0글자였다. 두 건 모두 자격 구간까지 잡혔다.
- **OCR은 차이가 가장 크다**(§3). OCR 두 줄은 모델을 받은 뒤 다시 돌린 값이다.

### 2.1 질적 예시

**병합 칸이 있는 표(hwp_table, 수원시 융자 공고)**: 기존 추출은 "자금구분 / 요건 ① / … / 운전자금 / 제조업 / 매출액 2억원 이상 / 전업률 30% 이상 / 5억원 …"처럼 칸이 한 줄씩 나열된다. 어느 한도가 어느 요건에 붙는지 글만 보고는 알 수 없다. kordoc은 병합 칸이 있으면 HTML `<table>`에 `rowspan`을 남긴다. 그래서 "운전자금·제조업·매출액 2억원 이상 → 5억원", "매출액 2억원 미만 → 3억원"처럼 요건과 한도가 짝지어진다. 조건 정규화에서 "요건 A이면 한도 B"를 뽑을 때 바로 쓸 수 있다.

**목록형 자격(hwpx_table, 울산 특별보조금)**: 두 결과의 글이 거의 같다. kordoc은 "2. 신청대상", "3. 신청서 접수방법" 같은 제목을 Markdown 제목(`##`)으로 표시한다. 구간 경계를 찾을 때 도움이 된다.

**배포용 HWP(인천 긴급 경영안정자금)**: 기존에는 읽지 못했다. kordoc은 지원대상·업종 각주·대상 국가 목록·지원 한도까지 모두 읽었다.

## 3. OCR(기존 Tesseract와 비교)

처음에는 `KORDOC_OFFLINE=1`로 모델 다운로드를 막아 OCR 10건이 빈 출력·실패였다. 2026-11-27에 사용자 승인을 받아 모델을 받은 뒤 같은 10건을 오프라인으로 다시 돌렸다.

- 받은 모델: PP-OCRv5 글자 위치 찾기(det, 약 5 MB), 한국어 글자 인식(rec, 약 13 MB), 글자 사전(약 1 MB). Hugging Face의 PaddlePaddle 저장소에서 받았고 kordoc이 SHA-256을 확인했다(`kordoc models --status`에서 verified). 수식 OCR 모델(Pix2Text)은 받지 않았다.
- 캐시 위치: 사용자 홈의 `.cache/kordoc/models/ppocr`. 다른 PC에는 `kordoc models --export <폴더>` → `--import <폴더>`로 옮긴다.
- `onnxruntime-node`의 설치 후 스크립트는 돌리지 않았지만, Windows x64용 실행 파일이 패키지에 들어 있어 그대로 동작했다.

| 지표(10건 합계·평균) | 기존 Tesseract | kordoc PP-OCRv5 |
|---|---|---|
| 한글 글자 수 | 3,853 | 6,471 |
| 한 글자 토큰 비율(평균) | 0.716 | 0.103 |
| 한글 토큰 평균 길이 | 1.4자 | 3.2자 |
| 자격 구간(ELIGIBILITY) 잡힌 문서 | 1 | 7 |
| 처리 시간(중앙값 / 최대) | — | 7.4초 / 60초(스캔 PDF 여러 쪽) |

- 기존 OCR은 "현 장 실 습 훈 련 지 원 사 업"처럼 거의 모든 글자가 띄어져 나왔다. 그래서 단어 검색과 구간 찾기가 거의 되지 않았다. kordoc은 단어 단위로 붙어 나온다.
- 포스터 이미지에서 "신청자격 | 지원내용" 같은 표를 `<table>`로 복원한 예도 있었다.
- 약점 1: 띄어쓰기가 빠지는 곳이 있다(예: "최소6개월이상고용하는기업"). 문자열 일치 규칙은 공백을 무시하고 비교해야 한다.
- 약점 2: 여러 단으로 된 포스터는 읽는 순서가 섞인다. 구간 경계가 틀릴 수 있다.
- 따라서 OCR 결과는 지금처럼 `OCR_LOW_TRUST` 표시를 유지하고, 자격 판정 근거로 쓸 때는 사람 확인을 거친다.

## 4. 위험과 주의

| 위험 | 대응 |
|---|---|
| 정답(gold) `evidence_references`의 글자 위치가 바뀐다 | 기존 추출을 **덮어쓰지 않는다.** 새 스냅숏(`extracted/<날짜>_kordoc/`)으로 만들고, 정답은 기존 스냅숏을 계속 가리킨다. 옮길 때는 근거 문장으로 다시 찾아 붙인다 |
| 아주 새 배포본(4.25.24, 2026-11-26)이고 개인 저장소다 | 정확한 버전을 고정하고 `package-lock.json`을 남긴다. 버전을 올릴 때는 이 표본으로 다시 비교한다 |
| Node(≥20) 의존이 생긴다 | 오프라인 일괄 추출에만 쓴다. API 서버(FastAPI)에는 넣지 않는다. 출력 Markdown만 파이썬 쪽이 읽는다 |
| 설치 용량(약 392 MB, 패키지 141개) | 저장소에 넣지 않는다. 설치 방법만 안내 문서에 적는다 |
| HTML 표가 섞인 Markdown | 정리층에서 `<table>`을 행 단위 레코드로 바꾸는 단계가 필요하다. `find_sections`는 지금처럼 태그를 지운 글로 돌린다 |

## 5. 권고

1. **채택(병행)**: HWP·HWPX·배포용 HWP는 kordoc 결과를 새 추출 스냅숏으로 만든다. 기존 추출은 그대로 둔다.
2. **표 활용**: 정리층에 "HTML 표 → 행 레코드" 변환을 넣고, 조건 정규화에서 표 안 요건·한도 짝을 쓰는지 개발용 30건으로 확인한다.
3. **PDF**: 글자 PDF는 차이가 작다. 당장은 기존(PyMuPDF)을 유지한다.
4. **OCR**: 스캔 PDF·이미지 126건은 kordoc으로 바꾼다. 차이가 가장 크다. 단, `OCR_LOW_TRUST` 표시와 사람 확인은 유지한다. 전체 126건을 돌리면 약 15~30분 걸릴 것으로 본다(표본 중앙값 7.4초·평균 14초 기준).
5. **정답 보호**: 정답이 가리키는 스냅숏은 바꾸지 않는다. 신규 데이터 파이프라인(`docs/DESIGN_신규데이터_파이프라인과_상위법령_v0.1.md`)의 스냅숏·`LATEST` 규칙을 그대로 따른다.

팀 결정이 필요한 것: 1(HWP 계열 병행 채택), 4(OCR 교체). OCR 모델은 이 PC에 이미 받아 두었다.
