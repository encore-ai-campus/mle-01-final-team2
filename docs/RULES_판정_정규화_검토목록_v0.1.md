## 이 문서 쓰는 법

- 규칙마다 **지금 동작**, **근거**, **영향 규모**, **선택지**를 적었다. **제안**은 작성자의 의견이다. 결정은 팀이 한다.
- **결정** 칸에 `유지`, `변경(선택지 번호)`, `보류` 중 하나와 결정한 날짜를 적는다.
- 결정한 규칙은 코드에 반영하고, 반영한 커밋을 **반영** 칸에 적는다.
- 상태 표시
  - `확정`: 설계서와 코드가 같고 결정도 끝났다. 확인만 하면 된다.
  - `결정 필요`: 설계서와 코드가 같지만 팀 결정이 없었다.
  - `불일치`: 설계서와 코드가 다르다. **먼저 정해야 한다.**

### C-5. 근거 없이 가정한 AND 요건의 강등

| 항목 | 내용 |
|---|---|
| 지금 동작 | 요건 R1(지역·연령·신청 대상 등)은 문장에 AND가 드러나지 않아 `logic_basis=assumed`다. 서비스 평가기는 이 표시를 읽지 않는다. 라벨 평가기(`label_eval.py:221`)는 `ASSUMED_LOGIC` 사유로 강등한다 |
| 설계서 | §4.3·§7: `assumed` 요건이 `ELIGIBLE`을 만들면 `NEEDS_CHECK`로 낮춘다 |
| 영향 | 요건 4,786개. 지금은 모든 공고가 본문 요건 미추출(`REQ_UNPARSED`)이라 `ELIGIBLE`이 나오지 않는다. 그래서 결과 차이가 아직 드러나지 않는다 |
| 선택지 | ① 서비스 평가기에도 `ASSUMED_LOGIC` 강등을 넣는다 ② 구조화 필드끼리의 AND는 근거가 있다고 보고(필드가 따로 있으므로) `logic_basis=explicit`로 바꾼다 |
| 제안 | ②. 구조화 필드는 서로 다른 필수 입력 칸이라 AND로 읽는 것이 맞다. 본문에서 뽑은 요건에만 `assumed`를 쓴다. 두 평가기가 같은 결과를 내는지 시험을 둔다 |
| 결정 / 반영 | |

### A-8. 공고 단위 판정과 강등 (확정)

hard 조건이나 hard 요건 중 하나라도 불충족이면 `NOT_ELIGIBLE`이다. soft 불충족이나 `UNKNOWN`이 있으면 `NEEDS_CHECK`다. 모두 충족이어도 본문 요건이 검수되지 않았으면(`text_requirements≠reviewed`) `REQ_UNPARSED`로 `NEEDS_CHECK`다. 지금은 5,116건 전부 `unparsed`라 `ELIGIBLE`이 나오지 않는다. 설계서 §7(3)과 같다. 확인만 하면 된다.

### A-9. OR 요건: 업력 또는 예비창업자 (확정)

업력 옵션이 "예비창업자, N년미만…"이면 요건 R2 = OR(업력 N년 미만, 예비창업자)이다. OR이 충족되면 그 안의 불충족 조건은 사유로 쓰지 않는다. 그래프 내보내기와 평가기가 같은 함수(`condition_schema.requirement_groups`)를 쓴다(PR #25). 바꾸기 전과 후의 판정은 9,822,720건에서 같았다.

## 5. 정의 판정 기준: 중소기업 (2026-11-26 추가)

`tools/graphrag/definition_rules.py`가 중소기업 정의의 판정 기준(`rule_json`) 초안을 만든다. 업종별 규모 기준은 기억이 아니라 수집한 시행령 별표 1(44행)·별표 3(43행) 원문을 행으로 풀어 만들고, 근거 조문·별표의 원문 해시를 함께 남긴다. 판정 순서는 S1 업종별 평균매출액등(별표 1) → S2 자산총액 5천억원 미만(시행령 제3조제1항제1호나목) → S3 독립성 → S4 공시대상기업집단 소속 아님(법 제2조제1항 단서)이고 넷 다 충족해야 중소기업이다. **초안이라 공고 판정에는 아직 쓰지 않는다.** 중소기업을 가리키는 공고 조건이 0개이고, 프로필에 업종·매출·자산 입력이 없다.

### E-1. 업종 코드를 별표 행에 맞추는 법

| 항목 | 내용 |
|---|---|
| 지금 동작 | 한국표준산업분류 코드의 앞부분이 가장 길게 맞는 행을 쓴다(`E36` 수도업이 `E` 폐기물 처리보다 먼저). 별표에 없는 업종(공공행정 `O`, 협회·단체 `S94` 등)은 UNKNOWN |
| 근거 | 별표 비고 1: 업종 분류는 한국표준산업분류를 따른다. 별표에 없는 업종의 기준은 별표만으로 정할 수 없다 |
| 선택지 | ① 유지 ② 별표에 없는 업종은 중소기업기본법 대상이 아니라고 보고 UNSATISFIED |
| 제안 | ①. 고시(시행령 제3조의3제4항)를 확인하기 전까지 모름으로 둔다 |
| 결정 / 반영 | |

### E-2. 매출 기준 경계와 산정 기준일

| 항목 | 내용 |
|---|---|
| 지금 동작 | "이하"를 그대로 비교한다(1,000억원은 충족, 1,000.5억원은 불충족). 업력과 달리 경계 UNKNOWN 구간이 없다. 입력한 평균매출액등이 시행령 제7조 방식(직전 3개 사업연도 평균 등)으로 계산한 값이라고 본다 |
| 근거 | 평균매출액등과 적용기간(제3조의3: 직전 사업연도 말일에서 3개월 지난 날부터 1년)은 기업 회계 자료로 정해진다. 사용자가 정확한 값을 모를 수 있다 |

| 결정 / 반영 | |

## 6. 회의 진행 제안

1. C-1 ~ C-6(불일치)을 먼저 정한다. 결정에 따라 설계서와 코드 중 한쪽을 고친다.
2. A-1, A-5는 프로필 입력 화면과 같이 정한다(입력 항목이 바뀐다).
3. B-3, B-4는 본문 요건 추출을 시작하기 전에 정한다.
4. D-1, D-2는 검수 패킷 검수를 시작하기 전에 정한다(검수 항목이 늘 수 있다).
5. E-2, E-5는 프로필 입력 화면과 같이 정한다(중소기업확인서로 받을지).
6. 결정한 규칙은 평가기 시험(`tools/test_graphrag.py`)에 사례로 넣는다. 정답셋 파일럿 라벨링은 이 결정을 기준으로 한다.
