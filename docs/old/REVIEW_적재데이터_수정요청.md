# 적재용 변환 데이터 점검 결과와 수정 요청 (v0.1)

> 대상: `neo4j_import.json`(공고 15건, 관계 6종 129건), `supabase_public_notice_chunks.json`(청크 15건, 공고당 1청크)
> 방법: 두 파일을 읽기 전용으로 점검했다. Neo4j·Supabase에 적재해 보지는 않았다.
> 기준: [MLE_2팀_기초 설계.md](../MLE_2팀_기초%20설계.md) §4~5, [SAMPLE_그래프관계_분석.md](SAMPLE_그래프관계_분석.md)

## 0. 결론

두 파일은 **메타 층 적재용으로 쓸 수 있다.** 형식과 참조 무결성은 문제가 없다. 다만 요건 층과 지역 관계가 없고 필드 의미가 소스마다 달라, 아래 수정(§2)을 거친 뒤 적재하는 것을 권한다.

## 1. 확인된 것 (수정 불필요)

| 항목 | 결과 |
|---|---|
| 인코딩 | 두 파일 모두 UTF-8, 깨진 글자(U+FFFD) 0건 |
| 공고 ID 일치 | 두 파일의 `notice_id` 15건 일치, `raw_hash` 15건 일치 |
| 관계 무결성 | 6종 129건에서 없는 공고·없는 대상 참조 0건, 중복 간선 0건 |
| 나라장터 식별 | 공고 ID에 차수 포함(`R26BK01834489:000`), 기관은 `ntceInsttCd` 코드 기준 |
| K-Startup 원문 보존 | `target_text`, `business_age_text`, `target_age_text`를 따로 보존(요건 추출 입력으로 사용 가능) |
| 임베딩 | `embedding`이 15건 모두 null. 임베딩 전 단계로 보이며 문제 아님 |

## 2. 수정 요청

우선순위: **높음** = 적재 전에 정리, **중간** = 요건 층 연결 전까지, **낮음** = 여유 있을 때.

|---|---|---|---|---|
| 1 | 높음 | `eligibility_text`의 의미가 소스마다 다르다 | 기업마당은 `trgetNm`("중소기업", "창업벤처")이 들어간다. 산청군 음식점 공고도 "중소기업"이라 청크에 `대상·자격: 중소기업`이 임베딩된다. 나라장터는 지역제한 기준 문구가 들어가고, K-Startup은 대상·서술·업력·연령을 줄바꿈으로 이어 붙인다 | 소스별로 필드를 분리하거나 이름을 `target_hint`처럼 바꾼다. 기업마당 요건은 `summary`의 ☞ 항목에 있으므로 청크에는 그쪽을 `대상·자격`으로 넣는다. K-Startup은 청크에서도 항목 라벨을 유지한다 |

## 3. 이 파일들에 없는 것 (예상된 범위)

`Requirement`, `Condition`, `Concept`, `Definition`, `Program`, `Track` 노드는 두 파일에 없다. 지금 구조(공고·기관·분야·태그)는 SQL 테이블과 같아서 그래프의 근거가 되지 못한다. 판정에 쓰는 요건 층은 [SAMPLE_그래프관계_분석.md](SAMPLE_그래프관계_분석.md) §3처럼 본문 추출로 별도 생성해야 하며, 이 파일은 그 입력(`summary`, `target_text`, `business_age_text`, `target_age_text`)을 제공하는 역할이다.
