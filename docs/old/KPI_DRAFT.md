## 0. 읽는 법과 원칙

1. **수업 예시는 출발점이지 우리 목표가 아니다.** 예시 표의 안내("실제 KPI 목표는 프로젝트 특성에 맞춰 설정")를 따라, 지표마다 **그대로 쓰는지·조정하는지·바꾸는지**를 §1에 적었다.
2. **잠정 목표는 측정 전의 가설이다.** 베이스라인(`base` 모델, 벡터 단독 검색)을 먼저 재고, **그 결과를 본 뒤 중간 발표 전에 확정**한다(§9). 아래 수치에는 근거를 달았지만 달성 가능성을 보장하지 않는다.
3. **합격선은 두 개로 쓴다.** 절대 하한과 "기준선 대비 하락 허용폭"(설계서 §9 회귀 게이트). 소형 모델 SFT로 판단 능력이 거의 오르지 않았다는 수업 사례(적용 0/21 → 1/21)가 있으므로, **판단 지표는 낙관하지 않는다.**
4. **안전 지표는 평균이 아니라 건수로 본다.** 비인가 접근 1건, 확정적 징계 표현 1건이 평균에 묻히지 않도록 "0건", "100%"를 목표로 둔다.
5. **표본이 작다는 점을 같이 적는다.** 평가셋이 60문항이면 1문항이 1.7%p다. 이 정도 차이는 해석하지 않는다(설계서 §9).
6. 대상 질문 유형·모드(사원/인사)가 있는 지표는 **모드별로 따로 센다.**

### 0.1 핵심 지표와 평가 우선순위 (2026-11-18 멘토링 반영)

멘토링에서 "목표값은 실제 베이스라인을 측정한 뒤 확정하고, 핵심 지표 중심으로 평가 우선순위를 정리하라"는 의견을 받았다. 지표가 60여 개라 모두 같은 무게로 보면 핵심이 흐려지므로 4개 층으로 나눈다.

| 층 | 의미 | 지표 | 목표를 정하는 방식 |
|---|---|---|---|
| **0. 게이트**(필수 준수) | 하나라도 어기면 인사 모드를 시연·배포하지 않고, 어떤 실험 결과도 "개선"으로 인정하지 않는다. 평균이 아니라 건수로 본다 | S-01 비인가 접근, S-02 감사 로그, S-04 확정 표현, S-06 사안 비저장, S-07 데이터 격리, **S-09 Unauthorized Retrieval Rate, S-10 Embedding Reconstruction Risk, S-11 Policy Violation Rate** | 베이스라인과 무관하게 **100% 또는 0건**(S-10은 §0.2). 기획 보고서 §4.4의 MR-01~05와 연결 |
| **1. 핵심 12개** | 발표와 판단의 중심. 이 중 **표준 지표 세트 9개**(§0.2)는 모든 비교 실험에서 함께 측정한다 | Q-01 Task Success, **Q-02 답변(판정) 정확도**, Q-04 인용 조문 일치율, Q-05 Faithfulness, Q-09 `판단 불가` 적절성, **Q-11 Evidence Coverage**, E-04 Recall@5, G-01 GraphRAG 개선 효과, P-01 첫 토큰 지연 p95, **P-05 GPU Cost**, **P-08 입력 토큰 수**, M-03 튜닝 효과 | **베이스라인 측정 후** 중간 발표 전 1회 조정해 확정(§10). P-05는 측정 필수이고 목표는 GPU·모델 확정 후 |
| **2. 보조** | 원인 분석과 품질 보강 | 위에 없는 Q·E·G·O·M 지표, S-03·S-05·S-08 | 측정·보고하며 목표는 참고값 |
| **3. 보고용·후순위** | 목표를 두지 않는다 | P-06 goodput, E-06 MRR | 측정값만 기록 |

**측정 순서:** ① `base` 모델 + 벡터 단독 검색으로 핵심 지표(Q-01·Q-04·Q-05·Q-09·E-04·P-01)의 베이스라인을 먼저 잰다. ② 그래프 확장을 더해 G-01을 잰다. ③ QLoRA·양자화 변형으로 M-03·M-05를 잰다. ④ 게이트는 배포마다 전수 점검한다.

**표기 규칙:** 베이스라인 값 없이 목표만 적지 않는다. 확정 전에는 문서·발표에 **"잠정"** 을 붙이고, 확정하면 결정 기록표(§10)에 근거(측정값·표본 수)를 남긴다. 아래 표의 모든 목표값은 이 규칙이 적용된다.

### 0.2 기업용 GraphRAG 실험의 표준 지표 세트와 개선 인정 규칙 (2026-11-18 추가)

기업용 GraphRAG 실험(문맥 압축, 모델 변형, 검색 전략, 에이전트 구성)은 **아래 9개 지표를 항상 함께 측정**한다. 효율 지표만 보고 "좋아졌다"고 판단하면 안 되기 때문이다. 특히 **문맥 압축에 성공하더라도 검색 근거가 손실되거나 보안 정책을 위반하면 기업용 시스템의 신뢰성이 개선됐다고 볼 수 없다.**

| 묶음 | 지표 | 이 문서의 ID | 무엇을 막는가 |
|---|---|---|---|
| 품질 | 답변 정확도 | Q-02 (Q-01 병행) | 틀린 판정 |
| 품질 | Faithfulness | Q-05 | 근거 없는 서술 |
| 품질 | Evidence Coverage | **Q-11** (신규) | 압축·검색 과정에서 근거가 빠짐 |
| 효율 | 입력 토큰 수 | **P-08** (신규) | 비싸고 느린 컨텍스트 |
| 효율 | Latency | P-01·P-02 | 느린 응답 |
| 효율 | GPU Cost | P-05 | 비용 |
| 보안 | Unauthorized Retrieval Rate | **S-09** (신규) | 권한 없는 자료가 검색·컨텍스트에 들어감 |
| 보안 | Embedding Reconstruction Risk | **S-10** (신규) | 임베딩에서 원문이 복원됨 |
| 보안 | Policy Violation Rate | **S-11** (신규) | 정책 위반 응답 |

**개선 인정 규칙(제안)**

| 순서 | 규칙 |
|---|---|
| 1 | **게이트 먼저.** S-01~S-02·S-04·S-06·S-07·S-09·S-10·S-11 중 하나라도 위반하면 그 실험은 "개선"으로 인정하지 않는다. 효율이 아무리 좋아도 채택하지 않는다 |
| 2 | **품질 하한.** Q-02·Q-05·Q-11이 기준선 대비 **허용 하락폭 이내**여야 한다. 허용 하락폭은 설계서 §9의 회귀 게이트 규칙(같은 설정 3회 반복의 흔들림 + 1/사례 수)을 따른다 |
| 3 | **그다음에 효율.** 1·2를 통과한 경우에만 P-08·P-01/P-02·P-05의 개선을 "개선"으로 보고한다 |
| 4 | **문맥 압축 예시.** 입력 토큰이 줄었지만 Q-11(근거 커버리지)이 허용 하락폭을 넘으면 "효율 개선, 신뢰성 악화"로 기록하고 채택하지 않는다 |
| 5 | **보고 형식.** 실험 결과표는 9개 지표를 모두 열로 둔다. 측정하지 못한 칸은 비우지 않고 **"미측정"** 으로 쓴다 |

위 지표 세트와 규칙은 **제안**이며, 목표값은 §10 절차(베이스라인 후 확정)를 따른다.

## 1. 수업 예시 KPI의 적용 방안

| 수업 예시 | 예시 목표 | 우리 프로젝트 적용 | 이유 |
|---|---|---|---|
| Task Success Rate | 90% 이상 | **조정** — 판정·근거 조문이 모두 맞아야 성공(§2 Q-01) | 에이전트 작업의 성공 조건을 우리 서비스 기준으로 정의해야 함 |
| Accuracy | 90% 이상 | **조정** — 판정 3분류(위반 가능 / 문제 없음 / 판단 불가) 정확도(Q-02) | 소형 모델·서술형 의무라 90%는 근거가 없음 |
| Precision / Recall / F1 | 85% / 85% / 0.85 | **분리 적용** — ① 지식 추출 ② 조항 후보 검색 ③ 파서 관계로 나눔(§3) | 한 숫자로 합치면 의미가 없음. 인사 모드는 **재현율(누락 방지)** 이 정밀도보다 중요 |
| Latency | 평균 3초 이하 | **바꿈** — 평균이 아니라 **첫 토큰 p95·전체 p95**(P-01·P-02) | Multi-hop + 스트리밍 응답이라 "평균 3초 완료"는 맞지 않음 |
| Error Rate | 2% 이하 | **그대로** | 5xx·타임아웃·빈 응답 기준 |
| RAG Faithfulness | 0.90 이상 | **조정** — 0.85에서 시작(Q-05) | 한국어 판사 신뢰도·소형 판사 문제(설계서 §9). 확정은 측정 후 |
| System Availability | 99% 이상 | **조정** — 시연·평가 기간 기준(P-04) | RunPod는 사용 시에만 구동(NFR-08), Aura Free는 일시중지 가능성(설계서 ADR-2) |
| Cost per Request | $0.01 이하 | **보류** — 산식만 정하고 목표는 GPU·모델 확정 후(P-05) | 모델 크기·GPU가 학원 예산에 따라 결정됨 |
| (없음) | — | **추가** — 근거 인용, 거절, 판단 불가, 검색, 온톨로지, 안전, 모델 비교, 에이전트, 메모리 | 규정 준수 도메인과 필수 요건(LoRA 전후, Guardrails 등)에 필요 |

## 2. 답변 품질 (사원·인사 공통)

평가셋: 설계서 §9의 유형 A/B/C/D + 후속 질문 + 근거 없는 질문 + 범위 밖 질문, **최소 60문항**, 최적화용과 최종 확인용(마지막 1회)을 분리한다.

| ID | 지표 | 정의 / 측정 | 잠정 목표 | 근거·비고 |
|---|---|---|---|---|
| Q-01 | **Task Success Rate** | 정답 질문 중 **판정과 근거 조문 id가 모두 gold와 일치**한 비율. 사원·인사 모드별 | 사원 80% 이상 / 인사 70% 이상 | 인사 모드는 사안→조항 매핑이라 더 어렵다고 보아 낮게 시작. 수업의 "적용" 지표가 낮았던 점 반영 |
| Q-02 | **판정 정확도 (Accuracy)** | 판정 3분류가 gold와 일치한 비율(사원 모드 행동 질문) | 80% 이상 | `판단 불가`를 정답으로 둔 문항 포함. 혼동행렬을 함께 보고 |
| Q-03 | **근거 인용 포함률** | 답변 중 조문 id가 1개 이상 인용된 비율(규칙 판정, 모델 호출 없음) | 95% 이상 | NFR-01. 결정적으로 셀 수 있어 목표를 높게 둠 |
| Q-04 | **인용 조문 일치율** | 인용한 조문 id가 gold 근거에 포함된 비율 | 85% 이상 | 존재하지 않는 조문 인용은 0건을 목표로 별도 집계(환각 인용) |
| Q-05 | **RAGAS Faithfulness** | 답변이 검색 근거에 충실한 정도(0~1). 한국어 `system_prompt` 지정, NaN 별도 확인 | 0.85 이상 | 예시 0.90에서 한 단계 낮춰 시작. **Faithfulness가 높아도 낡은 규정이면 틀리므로 Q-01·Q-04를 같이 봄** |
| Q-06 | **RAGAS Answer Relevancy** | 질문과 답변의 관련성 | 기준선 대비 하락 허용폭 이내 | 합격선은 팀이 정함(설계서 §9). 절대값은 측정 후 |
| Q-07 | **범위 밖·근거 없음 거절률** | 거절해야 할 질문에서 "근거 없음"이라 답한 비율 | 90% 이상 | 규정에 없는 내용을 지어내지 않는 핵심 지표 |
| Q-08 | **과잉 거절률** | 답해야 할 질문을 거절한 비율 | 10% 이하 | Q-07만 올리면 모든 질문을 거절하는 모델이 이김 → 한 쌍으로 본다 |
| Q-09 | **`판단 불가` 적절성** | 정보가 부족한 문항에서 결론 대신 `판단 불가` 또는 되묻기를 한 비율 | 80% 이상 | FR-21. 인사 모드에서 억지 결론을 막는 지표 |
| Q-10 | **후속 질문 정답률** | 맥락 의존 후속 질문(`followup`)의 정답률. 기억 on/off 비교 | 사원 모드 75% 이상, 기억 on이 off보다 높을 것 | 설계서 §8 메모리 |
| Q-11 | **Evidence Coverage** | gold 근거 조문(과 정답 경로의 간선) 중 **최종 응답이 인용·표시한 비율**. 검색 단계의 Recall(E-04)과 달리 압축·생성을 거친 뒤의 값이다 | 80% 이상(잠정) | Q-04(인용이 맞는가, 정밀도 성격)와 짝으로 본다. 문맥 압축 실험의 핵심 손실 지표. 모델 호출 없이 id로 셀 수 있음 |

## 3. 정밀도·재현율·F1 (대상별로 분리)

| ID | 대상 | 정의 / 측정 | 잠정 목표 | 근거·비고 |
|---|---|---|---|---|
| E-01 | **의무·예외 추출 F1** (추출 층) | 핵심 문서 골드셋(추출 결과를 보지 않고 직접 작성)과 대조한 관계 단위 P/R/F1 | **F1 0.70 이상** | 서술형 의무가 대부분이고 소형 모델이라 예시 0.85는 보류. 수치·기한 항목은 규칙 병행 |
| E-02 | **추출 스키마 준수율·근거 원문 일치율** | JSON 스키마 통과 비율 / `evidence`가 원문에 그대로 존재하는 비율 | 스키마 95% 이상, 근거 일치 100%(불일치는 적재 금지) | 온톨로지 설계서 §6.3: 근거 없으면 만들지 않는다 |
| E-03 | **파서 관계 정밀도** (결정 층) | `REFERS_TO`·`CITES`·`IMPLEMENTS` 표본 검수(모집단 명시, 0/1 판정) | 정밀도 95% 이상 | 규칙으로 만드는 층이라 높게 둠. 표본 크기·합격선은 **결과를 보기 전에** 정함 |
| E-04 | **조항 후보 검색 Recall@5** | gold 근거 조문 중 상위 5개에 포함된 비율(ID 기반, 모델 호출 없음) | **85% 이상** | 인사 모드는 **누락이 더 위험**하므로 재현율 우선. 예시 85% 유지 |
| E-05 | **조항 후보 Precision@5** | 상위 5개 중 gold 비율 | 50% 이상 | 후보 제시 서비스라 정밀도는 낮게 허용. 사람이 거름 |
| E-06 | **MRR@5** | 정답 조문의 역순위 평균 | 기준선 대비 개선 | 절대값은 측정 후 |

## 4. GraphRAG·Multi-hop 효과

| ID | 지표 | 정의 / 측정 | 잠정 목표 | 근거·비고 |

### 4.1 에이전트 아키텍처 비교 실험 (A~E, 2026-11-18 추가)

에이전트 구성을 하나씩 더해 가며 **무엇이 얼마나 개선하는지**를 보는 비교 실험이다. 같은 평가셋·같은 모델·같은 설정으로 돌리고 3회 반복한다. 모든 군은 §0.2의 표준 지표 9개를 함께 보고하며, 아래 "군별 추가 지표"는 그 군이 겨냥하는 효과를 보는 지표다.

| 군 | 아키텍처 | 우리 설계에서의 대응 | 군별 추가 지표 |
|---|---|---|---|
| A | Multi-Agent + 메모리 없음 | 메모리 노드(`memory_load`·`memory_update`)를 끈 기준 구성 | TSR(Q-01), Latency |
| B | Multi-Agent + 요약 메모리 | `session_summaries`의 요약만 주입(설계서 §8) | TSR, **Memory Error Rate** |
| C | Multi-Agent + 근거 연결형 메모리 | 메모리 항목마다 근거(조문 id, 원 메시지 id)를 함께 저장하고 주입 때 확인. **현재 설계(ADR-7)에 근거 링크 필드가 없어 추가가 필요**(설계 변경 제안) | TSR, **Evidence Traceability** |
| D | C + Independent Evaluator | 답변 모델과 **분리된** 평가기(다른 모델·프롬프트)가 근거 지지와 정책 위반을 점검. 현재 Reflection은 같은 모델이므로 교체·추가가 필요(설계서 §7.1, §9 판사 분리) | **오류 탐지율**, **정책 위반율**(S-11) |
| E | D + Self-Healing | 실패를 감지해 자동 복구: 질의 재작성, 모델 폴백·서킷브레이커, 검색 전용 모드(설계서 §3, §7.1, §7.3) | **Recovery Rate**, **MTTR**, Cost(P-05) |

**군별 지표 정의(제안)**

| 지표 | 정의 |
|---|---|
| Memory Error Rate | 메모리(요약·기억 항목) 중 원 대화나 근거와 모순되거나 낡은 항목의 비율(표본 검수), 그리고 그 항목이 답변에 주입되어 오답을 만든 건수 |
| Evidence Traceability | 답변의 근거와 주입된 메모리 항목 중 **조문 id 또는 원 메시지까지 거슬러 갈 수 있는** 비율 |
| 오류 탐지율 | 오답·근거 불일치 답변(의도적으로 결함을 넣은 사례 포함) 중 평가기가 잡아낸 비율. **오탐률을 함께 보고**하고 사람 라벨과의 일치(M-07)로 신뢰도를 확인 |
| Recovery Rate | 모의 장애(모델 서버 중지, 검색 실패, 타임아웃)에서 **자동 복구로 정상 응답 또는 허용된 degrade 응답**에 도달한 비율 |
| MTTR | 장애 발생부터 정상 응답 복귀까지의 평균 시간. P-07과 같은 장애 주입 시험으로 잰다(목표는 리허설 측정 후) |

**실행 시 유의(제안)**
- **인사 모드는 메모리를 쓰지 않는다**(사안 비저장, MR-02). 따라서 B·C 비교는 **사원 모드에서만** 한다.
- 평가셋이 60문항이면 1문항이 1.7%p라 5개 군의 작은 차이는 해석할 수 없다. **A·C·D를 먼저** 비교하고, E는 장애 주입 시험으로 따로 한다. 일정이 부족하면 B를 생략한다.
- 개발 단계는 A가 P0 기본 구성, B·C·D는 P1, E는 P2로 둔다(기획 보고서 §1.3).
- 군이 올라갈수록 호출이 늘어 Latency·입력 토큰·GPU Cost가 커진다. **품질 개선이 비용 증가를 정당화하는지**를 §0.2 규칙으로 판단한다.

## 11. 한계와 미확인

- **모든 목표값은 측정 전 추정이다.** 특히 Q-01·E-01·G-02는 소형 모델 품질에 크게 좌우되며, 모델 크기·GPU가 미정이다.
- 인사 모드 평가셋은 **가상 사안**으로 만들며 실제 직원 사례를 쓰지 않는다. 가상 사안의 난이도가 실제를 대표하지 않을 수 있다.
- RAGAS는 영어 지시문 기반이라 한국어에서 점수가 흔들릴 수 있고, 수업의 판사는 외부 API였다. **자체 호스팅 소형 판사의 신뢰도는 수업에 없어** M-07로 직접 확인해야 한다.
- 에이전트 지표(G-05)와 법령·사규 연결률(O-01)의 정의는 우리가 정한 것이다.
- Aura Free·RunPod의 한도와 가용성은 확인하지 않았다(P-04, O-08).
- 이 문서는 법적 판단·징계 결정의 정확도를 보증하지 않는다. 서비스는 검토 보조 도구다.
