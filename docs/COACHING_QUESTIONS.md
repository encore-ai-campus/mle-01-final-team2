# 현업 개발자 코칭 질의서

> 목적: 현업 개발자 코칭에서 "우리가 이미 정한 것"보다 "우리가 틀렸을 가능성이 큰 곳"을 중심으로 조언을 받는다.
> 프로젝트: IBK기업은행 사규 + 상위 법령 기반 GraphRAG 규정 준수 검토 서비스 (사원 모드 / 인사 모드)

## 우선순위 3문항 (시간이 짧을 때)

1. GraphRAG가 일반 RAG보다 나은 질문 유형은 무엇이고, 그걸 어떻게 증명하나?
2. 남은 기간 안에 끝낼 MVP는 어디서 자르나?
3. 인사 모드를 유지해도 되나? (책임·개인정보 문제)

---

## 1. 주제·범위

| # | 질문 | 왜 묻는가 |
|---|---|---|
| 1-1 | 조문 단위 청킹 + 벡터 검색 + 참조 조항 확장만 하는 일반 RAG와 비교해, GraphRAG가 이기는 질문은 무엇인가? 비교 실험(baseline vs GraphRAG)은 어떻게 설계하면 설득력이 있나? | 우리 근거는 `REFERS_TO`/`IMPLEMENTS`/`DELEGATES_TO`를 따라가는 multi-hop 질문. 실제 비중과 증명 방법이 필요 |
| 1-2 | 현업에서 규정 검토는 어떻게 진행되나? 우리 시나리오(사원 질의, 인사 사례 검토)는 현실적인가? | 사용자 가정 검증 |
| 1-3 | 인사 모드의 범위와 책임 문제. "위반 가능성이 있는 조항 후보" 표현 + 사례 본문 미저장이 충분한 안전장치인가? 사원 모드 하나로 줄여도 되나? | 리스크 대비 가치 판단 |
| 1-4 | 남은 기간 안에 끝낼 수 있는 최소 범위(MVP)는 어디까지인가? 무엇을 버리나? | 현재 설계가 큰 편 |

## 2. 아키텍처·기술 스택 (과설계 점검)

| # | 질문 | 왜 묻는가 |
|---|---|---|

| 2-4 | RunPod vLLM의 비용과 콜드스타트를 시연·평가 기간에 어떻게 운영하나? | 비용·지연 |

## 3. 온톨로지·데이터 (우리 차별점)

| # | 질문 | 왜 묻는가 |
|---|---|---|
| 3-1 | 조문 노드에서 Obligation/Exception까지 추출하는 게 실익이 있나? 결정적 계층(파서)만으로 충분하지 않나? | LLM 추출·검수 비용 대비 효과 |
| 3-2 | 법령 개정과 시점 관리(`effective_date`)를 현업에서는 어떻게 하나? 어디까지 지원해야 하나? | 개정 민감도 |

| 3-4 | ALIO·Hugging Face 데이터의 재배포·라이선스 리스크. 공개 저장소에 올려도 되나? | 공개 전 필수 확인 |
| 3-5 | Aura 무료 한도(노드/관계)와 벡터 pre-filter 지원 여부는 어떻게 검증하나? | PoC 항목 |
