# 2-2단계 조건 추출 품질 진단 및 규칙 개선

작성일: 2026-11-25. 입력 표본은 2-1 개발용 80건만 사용했다. 평가용 20건은 추출 및 규칙 개선에 사용하지 않았다.

## 기준선 보존 및 실행 산출물

개선 전 출력은 `data/condition_inputs/v1/20261125/extracted/baseline/`에 복사해 보존했다. 진단과 표본은 `data/condition_inputs/v1/20261125/quality_diagnostics/`, 개선 출력은 `data/condition_inputs/v1/20261125/extracted/improved/`에 저장했다.

사람 검수 파일 `human_review.jsonl` 및 `human_review.csv`는 동일한 30개 공고를 기준선과 개선 출력, 원문, 연결 후보와 나란히 보여준다. 자동 의심/검수 상태는 `UNREVIEWED`이며 검수 보정값과 의견은 빈 칸으로 둔다. LLM 검토 후보는 `llm_assistance_candidates.jsonl`이다.

## 공고별 기준선 진단

| 지표 | 결과 |
|---|---:|
| 개발 공고 | 80 |
| 조건 후보 0개 | 29 |
| 조건 후보 1개 | 34 |
| 조건 후보 2개 이상 | 17 |
| 기준선 후보 수 | 84 |
| 미검토 대기열 | 29 공고 |
| BIZINFO 후보 평균/최대 | 0.78 / 4 |
| K-Startup 후보 평균/최대 | 1.32 / 6 |

0건은 규칙 매칭 실패일 뿐 조건 없음이 아니다. 원문 길이에 비례한 추출률은 정확성 지표가 될 수 없어 계산하지 않고 공고별 원문 길이와 후보 수를 검수 자료에 둔다.

## 기존 후보 연결 진단

개발 표본 80건에 연결된 기존 후보 참조 650개를 확인했다. 기준선은 2개를 근거 구간/속성 기준으로 연결했고, 648개는 연결되지 않았다(원문 구간/추출 범위 불일치 450, 현재 규칙이 다루지 않는 카테고리 198). 개선 결과는 258개 링크(249개 고유 참조)를 61개 생성 후보에 연결했다. 이 문자열 포함·속성 대응은 자동 후보 연결이지 의미상 재사용 확정이나 검수 완료가 아니다. 392개 참조는 여전히 연결되지 않아 개별 사유 검수가 필요하다.

기존 후보 중 중복 legacy ID 그룹은 개발 표본에서 46개다. 충돌 후보를 조건 출력에서 병합하거나 삭제하지 않았으며 provenance 연결을 복수로 유지한다. `not_found` 후보는 원문 조건으로 변환하지 않는다.

## 규칙 개선 및 전후 비교

개선은 공식 지역명에 대한 짧은 지역 별칭 매칭을 추가해 복수 지역 표현의 누락을 줄였다. 원래 자격/제외/우대 및 수치 규칙은 유지했다. 해시 condition ID는 개인정보 전화번호 패턴에 우연히 걸리는 오탐이 한 건 있어 base32 안전 인코딩으로 바꿨다. 원문과 정규화 입력은 변경하지 않았다.

| 지표 | 기준선 | 개선 |
|---|---:|---:|
| 처리 공고 | 80 | 80 |
| 조건 후보 | 84 | 98 |
| 자격/제외/우대 | 75 / 6 / 3 | 89 / 6 / 3 |
| 미분류 후보 | 9 | 9 |
| 후보 0개 공고 | 29 | 26 |
| 고유 condition ID | 84 | 98 |
| 스키마 오류 | 0/84 | 0/98 |
| 판정 허용 | 0 | 0 |
| 개인정보 검사 위반 | 기준선은 사후 PII regex 오탐 1건(ID만) | 0 |

후보 수 증가는 정확도 개선을 뜻하지 않는다. 사람 정답 라벨이 없으므로 Precision/Recall/F1은 계산하지 않았다. 자동 분석으로 보장할 수 없는 조건 유형·범위·수치 기준은 검수 대상으로 둔다.

## 실패 및 미지원 패턴

- `MISSING_CONDITION` 의심: 개선 후에도 규칙 결과가 없는 26개 공고. 조건 부재가 아니라 `NO_RULE_MATCH`/검수 대기다.
- `UNSUPPORTED_PATTERN`: 0개 후보 중 숫자·문장 범위 밖의 자연어 및 미지원 카테고리. 별도 LLM 후보와 사람 검수 파일에 남겼다.
- `LOST_CONTEXT` / `LOST_EXCEPTION`: 문장 내 연결어·예외는 후보 원문 조각과 원문 전체 입력에서 확인할 수 있지만, 구조화된 적용 범위 및 qualifier로 자동 연결하지 않는다. 검수 필요.
- `CONFLICTING_CANDIDATE`: 2-1 후보의 충돌 그룹은 기존 reference를 유지한다. 자동으로 하나를 선택하지 않는다.
- 비교연산자 이내는 현재 LTE 후보로 매핑하되 포함 경계는 검수 필요. 기준일은 UNKNOWN이다. 범위 BETWEEN 및 단위 환산은 미구현.

## LLM 보조 판단

규칙 사전 확장으로 처리할 수 있는 짧은 기업 유형/지역 표현은 규칙 후보로 유지한다. 장문 맥락, 생략 주어, 예외가 여러 문장에 걸친 경우, 규칙 후보가 서로 충돌하는 경우는 LLM 보조 검토에 적합하다. 현재 LLM 클라이언트는 미설정이므로 호출은 0회이며, 결과를 생성하지 않았다. LLM 후보도 검수 완료로 승인하지 않는다.

## 검증

실행 명령:

```powershell
.\.venv\Scripts\python.exe tools\diagnose_condition_extraction.py
.\.venv\Scripts\python.exe tools\extract_condition_candidates.py
.\.venv\Scripts\python.exe -m unittest tests.test_condition_extractor tests.test_condition_inputs tests.test_normalize_support_data tests.test_public_notice_pipeline tests.test_g2b_normalization tests.test_condition_schema -v
```

결과: 신규 및 기존 테스트 **41개 통과**. 개선 조건 객체 98건 스키마 오류 0, 고유 ID 98/98, PII 검사 위반 0, 판정 허용 0. 사람 정답 검수는 아직 수행하지 않았다.

2-3단계는 **사람이 확인할 미검수 후보의 논리 관계 구조 초안**에 한해 준비 가능하다. 자동 논리 트리 확정이나 판정은 추출 조건의 사람 검수 후 진행해야 한다.
