# 샘플 데이터 기반 그래프 관계 분석 (v0.1)

> 목적: 동료가 받은 API 샘플 15건(기업마당 5, K-Startup 5, 나라장터 5)으로 **그래프 관계를 만들 수 있는지** 확인하고, 요건 정규화 정답 세트의 시작점을 만든다.
> 근거 파일: `bizinfo_5.json`, `kstartup_5.json`, `g2b_5.json` (2026-11-17~20 수집분, 비무작위 각 5건).
> 상태: **손으로 읽은 초안**이다. 요건 추출기와 Neo4j는 아직 실행하지 않았다. 아래 정규화 값은 검수 전 가설이며, 법령 기준은 원문 확인 전이다.

---

## 0. 요약

| 질문 | 답 |
|---|---|
| 샘플로 그래프 관계를 만들 수 있는가 | **가능**하다. 다만 두 층으로 나뉜다. |
| ① 메타 층(공고·기관·분야·지역·분류) | 구조화 필드만으로 자동 생성된다. SQL 테이블과 구조가 같아 그래프의 근거가 되지 못한다. |
| ② 요건 층(자격 조건·정의·법령) | 본문 텍스트를 추출해야 한다. 기업마당·K-Startup 10건은 손으로 정규화할 수 있었다. 나라장터 5건은 자격이 첨부에 있어 **정답 세트를 만들 수 없었다.** |
| 설계에 없던 것 | N-of-M 논리, 논리 명시 여부, 구조화 필드와 본문의 충돌 규칙, 개인 대상 속성 등 15건. §4에 정리하고 기초 설계서에 반영했다. |
| 그래프 필요성 증거 | **늘지 않았다.** 다중 hop이 실제로 필요한 곳은 10건 중 3건(경상권 정의, 식품위생법 연결, N-of-M)이다. |

## 3. 요건 층: 손 정규화 초안 (정답 세트 시작점)

표기: `속성 연산자 값`. `kind`는 ELIGIBILITY(E), EXCLUSION(X), LIMIT(L), DOCUMENT(D). `논리`가 *가정*이면 본문에 AND/OR 명시가 없다는 뜻이다(F3).

## 4. 발견 사항과 설계 반영

| # | 발견 | 근거 건 | 반영 |
|---|---|---|---|
| F1 | **N-of-M 요건**을 AND·OR로 표현할 수 없다 | K5 | `Requirement.logic`에 `AT_LEAST` 추가, `min_count` 속성 추가. 3값 결합 규칙은 §5.1. **반영함** |
| F2 | 대상별로 추가 조건이 붙는 요건 | B5, K1, K4 | 기존 `Track`으로 모델링한다. 트랙이 있으면 **트랙별 판정 후 하나라도 `ELIGIBLE`이면 공고는 `ELIGIBLE`(해당 트랙 표시)**, 모두 `NOT_ELIGIBLE`이면 `NOT_ELIGIBLE`, 그 외 `NEEDS_CHECK`. **반영함** |
| F3 | 조건을 나열만 해 AND/OR가 불명확한 요건 | B2 외 다수 | `Requirement.logic_basis`(`explicit`/`assumed`) 추가. `assumed`인 요건이 결과를 `ELIGIBLE`로 만들면 `NEEDS_CHECK`로 낮춘다(검수 전까지). **반영함** |
| F4 | 구조화 필드와 본문이 충돌한다 | K1(`biz_enyy`), K2·K4(`supt_regin`), K4(`biz_trgt_age`) | **본문 우선**. 충돌은 `source_conflict`로 기록하고 설명에 표시한다. 구조화 필드는 후보 생성과 검증용이다. **반영함** |
| F5 | 목록형 구조화 값의 의미 | K2, K3, K5(`biz_enyy`, `biz_trgt_age`) | 값이 전체 구간이면 **제한 없음**(조건 생략), 일부면 OR 합집합으로 읽는다. **반영함** |
| F6 | 기업마당 `trgetNm`이 거칠다 | B2, B5 | 5건 중 2건(음식점, 농업인)이 "중소기업"이다(내 판단, 비측정). **판정에 쓰지 않고** 참고 속성으로만 둔다. **반영함** |
| F7 | `excInsttNm`이 기관명이 아니라 범주값 | B2~B5 | 5건 중 4건이 "기초자치단체". 수행기관 이름은 `refrncNm`·본문에서 얻는다. **반영함** |
| F8 | 개인(근로자) 대상 공고 | B1 | `applicant_type`에 개인 유형 추가 필요, 속성 `tenure_years`. **팀 결정**(§6) |
| F9 | 속성·kind가 부족하다 | `tenure_years`, `career_years`, `capital`, `funding_stage`, `membership`, 입주 후 의무 | 속성 허용 목록 확장안과 `OBLIGATION` kind 추가안을 **팀 결정**으로 올린다. |

## 5. 판정 규칙 보완과 시험 케이스

### 5.1 `AT_LEAST(k)`의 3값 결합 (제안)

조건이 n개, `SATISFIED` s개, `UNSATISFIED` u개, `UNKNOWN` m개(s+u+m=n)일 때:

| 결과 | 조건 |
|---|---|
| `SATISFIED` | s ≥ k |
| `UNSATISFIED` | s + m < k (남은 미확인을 모두 충족해도 k에 못 미침) |
| `UNKNOWN` | 그 외 |

### 5.2 판정 시험 케이스 (검수 전 기대값)

기대값은 내가 §3 정규화 초안으로 손으로 계산한 것이다. 정규화가 틀리면 같이 틀린다.

| 프로필 | 공고 | 기대 판정 | 이유 |
|---|---|---|---|
| P1 경기 성남 거주, 여성, 예비창업자, 만 32세 | K1 | `ELIGIBLE`(T1) | 지역·유형·성별 모두 충족(공고일 기준 주소는 가정) |
| | K4 | `NOT_ELIGIBLE` | 성남 ∉ 경상권 → 두 트랙 모두 지역 불충족 |
| | K3 | `ELIGIBLE` | 조건 없음(선착순 정원 표시) |
| | K2 | `NEEDS_CHECK` | 대전 요건 불충족이나 "등" 열린 목록(F12), 구조화는 전국이라 충돌 표시 |
| P2 경남 창원 거주, 사업자 없음, 만 24세 | K4 | `ELIGIBLE`(T2) | **창원 → 경남 → 경상권** 2 hop, 만 39세 이하 |
| | K1 | `NOT_ELIGIBLE` | 창원 ∉ 경기도 |
| | B3 | `NOT_ELIGIBLE` | 남해군 거주 아님 |
| P3 경남 함안 농업인, 만 45세, 등록 여부 미입력 | B5 | `NEEDS_CHECK` | 지역·유형 충족, 농업경영정보 등록 `UNKNOWN` |
| | B3, B4 | `NOT_ELIGIBLE` | 지역·연령 불충족 |
| P4 서울 중기업 임직원, 근속 5년 | B1 | `ELIGIBLE` | 중기업 IS_A 중소기업(**법령 정의 연결, 원문 확인 필요**), 근속 ≥ 3 |
| | K5 | `NEEDS_CHECK` | AT_LEAST(3)에서 s ≤ 1, m ≥ 3이라 결정 불가 |

## 7. 한계

- 샘플은 포털당 5건이며 비무작위다. 비율 주장에 쓸 수 없다.
- §3은 한 사람의 해석이다. 두 검수자의 일치율은 아직 측정하지 않았다(D5).
- 법령 기준(중소기업·여성기업 등)은 원문을 확인하지 않았다.
- 첨부(hwpx) 본문을 읽지 않았다. B3의 "공고문 참조" 같은 요건은 첨부에 있어 정답이 불완전하다.
- 그래프가 SQL보다 필요하다는 증거는 이 샘플로 늘지 않았다. 다중 hop이 쓰인 곳은 K4 경상권, B2 식품위생법, K5 N-of-M 정도다.
